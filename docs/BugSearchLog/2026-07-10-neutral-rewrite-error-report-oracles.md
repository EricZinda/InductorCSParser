- Neutral-rewrite error-report oracles (backlog 0a02) added to the grammar fuzzer, campaigns clean, no divergence
    - Method: user-directed at backlog 0a02 rather than a random-walk file read. The property under test comes from that item: rewriting a grammar in a way that can't change what it matches shouldn't change what a failing parse reports. Implemented as three new oracles (7 through 9) in GrammarFuzzHarness next to the existing six, sharing the same generator, seeds, and inputs: wrap the whole grammar in one extra And, replace Exactly(n, x) with an And of n references to one shared x instance, and reverse the alternatives of an Or whose branches provably can't compete. Every rewritten grammar must agree with the original on outcome, ErrorCharIndex, ErrorMessage, and the success tree. The item's fourth rewrite (unnamed Alias wrap) was already oracle 4.
    - Eligibility rules that keep the rewrites sound live in FuzzRewriter, derived from Lexer.Failures.cs and docs/ErrorArchitecture.md. The Exactly rewrite needs an inner that consumes on every success, because the count rule stops its loop after one zero-width success while the And form doesn't (Exactly(2, Optional(a)) fails on empty input, And(Optional(a), Optional(a)) succeeds). The And repeats one shared inner instance rather than building the inner twice, because a second build would duplicate any .As name inside it. The Or reversal needs every branch to consume on success, have a computable exact first-token set with the sets pairwise disjoint (compared in FormC), and have no .WithError anywhere in its subtree, because equal-depth named and forced failures tie-break on first writer, and reordering legitimately flips that. What's left after those rules is order-blind: at most one branch can match, every rejected branch fails mechanically at the Or's start, and the mechanical tracker is a pure position max.
    - The oracles can actually fire, the green runs aren't dead comparison code: temporarily deleting each eligibility rule makes the standard 2000-seed run fail immediately with exactly the failure the rule predicts. Without the consuming rule, the Exactly-to-And oracle reports outcome flips on zero-width inners (Exactly(3, x) fails where AndSharedRepeat(3, x) succeeds). Without the branch rules, the Or-reorder oracle reports outcome flips from moved catch-all branches, error-position changes, and same-position .WithError message swaps (err0 vs err1 at the same index, forced included). Both weakenings were reverted after confirming.
    - Volume: the standard 2000-seed CI test is green under both engines and now asserts minimum comparison counts for the two conditional rewrites, so a generator regression can't quietly idle them. The 100K-seed deep campaign is green under both engines. A one-off extended campaign over fresh seeds 100K to 400K (scratch [Explicit] test, removed after the runs): 3,526,984 cases, 514,966 successful parses, 271,070 Exactly-rewrite comparisons, 30,085 Or-reorder comparisons, zero divergences on the recursive engine (11m) and again under INDUCTOR_DEFAULT_ENGINE=statemachine (52m). The And-wrap oracle runs on every case.
    - A deep review pass on 2026-07-20 hardened the harness without changing oracle behavior on current inputs: the EndOfLine first-token clusters now derive at runtime from TokenSet.LineTerminators (a ContainsRune scan of every code point plus EnumerateMultiRuneGraphemes) instead of being a third hand-written copy of the terminator list, the FuzzListNode switches throw on an unknown kind instead of disagreeing about the default arm (BuildCore treated non-And as Or while the first-token scan treated non-Or as And, an under-approximation trap for any future kind), the Exactly rewrite refuses Count 0 (And() rejects an empty child list), the PreserveAllSymbols oracle compares full Outcome rather than the Success boolean, the three rewrite variants' successes now run the SourceRange checks like the alias and lateBound variants always did, rewrite-compile divergences name the failing variant and show its expression, and the stale or overstated comments were corrected (the DumpNamed and DumpBySourceText role lists, the deep campaign's runtime estimate, the volume-floor note in the fixture comment, and the Or-reversal justification, which now states the real argument: the one branch whose set holds the input's first token can fail deep, and its records are identical in either order, so only the branches that fail at the Or's start plus the pure-max mechanical slot make reversal invisible).
