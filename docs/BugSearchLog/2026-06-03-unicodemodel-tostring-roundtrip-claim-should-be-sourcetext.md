    - Found and fixed (doc bug, not engine): docs/UnicodeModel.md said callers who want "character-exact round-trippability (where tree.ToString() must match the original input string character for character) compile with null." tree.ToString() rebuilds text only from the nodes left in the tree, so it drops every Delete child, and Token / Literal default to Delete. A normal grammar like `And(Literal("hello"), Token(','), Literal("world")).As("greeting").Compile(null)` parsing "hello,world" gives tree.ToString() == "" while tree.SourceText == "hello,world". SourceText is the verbatim accessor, and it round-trips under every form (it translates back to original coordinates), not just null. Symbol.cs's own ToString XML doc already says "To get the exact input verbatim, ... read SourceText", so the doc contradicted the API. The doc was the one user-facing surface with no DocExamples backing test (the ozpb gap), which let the claim sit wrong.
