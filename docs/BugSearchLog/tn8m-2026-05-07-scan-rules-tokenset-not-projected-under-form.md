- 2026-05-07: ScanWhile / ScanUntil TokenSet not projected under Compile's normalization form
    - Random-pick area: started from a random number against the `src/InductorParser/*Rule.cs` listing (23 → `ScanWhileRule.cs`), and read it side-by-side with `OneOfRule.cs`, `NoneOfRule.cs`, `ScanUntilRule.cs`, `LiteralRule.cs`, `LiteralIgnoreAsciiCaseRule.cs`, `GraphemeRule.cs`, `Rule.cs` (`Compile(NormalizationForm?)` orchestration, `CollectNormalizationOffendersAll`, `ComputeRuleStartAll`), `TokenSet.cs` (`NormalizedFor`), and the cross-check tests in `NormalizationTests.cs`.
    - Categories: form-projection of caller-supplied TokenSets, parallel between OneOf / NoneOf and the scan-shaped rules, cached static-analysis vs. mutated rule data (a000), `_set` mutability under `readonly`.
    - Found and fixed (tn8m): `ScanWhileRule._set` and `ScanUntilRule._stopperSet` were declared `readonly` and neither rule overrode `Rule.CollectNormalizationOffenders`. The Compile-time normalization-form pass walks `OneOfRule.NormalizeAndValidate(...)` to project user-typed precomposed / decomposed / canonical-singleton entries onto the lexer-normalized form (single-rune entries that decompose to multi-rune-but-single-grapheme become multi-rune entries; canonical-singleton substitutions like U+212B → U+00C5 swap rune values; multi-grapheme conversions like ﬁ → "fi" report as offenders). Without the override, ScanWhile and ScanUntil sets stayed in their pre-projection shape, and a stopper / matcher written as `é` (U+00E9) silently failed to match the FormD-normalized cluster `e + U+0301` even though OneOf with the same set / same input matches.
    - The fix dropped `readonly` from both fields and added a `CollectNormalizationOffenders` override that calls `OneOfRule.NormalizeAndValidate(this, ref _set, form, offenders)` (or `_stopperSet` for ScanUntil, gated on `_stopperRule == null` since rule-mode stoppers handle their own normalization through the walker's recursion into Children). Regression tests in `ScanWhileRuleTests.ScanWhile_with_precomposed_set_entry_matches_decomposed_input_under_FormD` and `ScanUntilRuleTests.ScanUntil_with_precomposed_stopper_set_stops_at_decomposed_input_under_FormD`. Full suite: 1905 / 1907 (2 pre-existing skips) before the fix, 1907 / 1909 after (the two new tests, plus the same 2 skips).
    - Sibling-rule check: `LiteralRule.CollectNormalizationOffenders` and `LiteralIgnoreAsciiCaseRule.CollectNormalizationOffenders` already mutate their `_expected` strings under the same Compile pass; `GraphemeRule.CollectNormalizationOffenders` does the same plus the rune-id re-pin (with the `IsUserSymbolIdPinned` skip xpid added). `OneOfRule` and `NoneOfRule` were the original users of `NormalizeAndValidate`. The four scan / one-of-style rules now form a complete set of TokenSet-bearing rules that participate in form projection.
    - Out of scope and worth a follow-up: the `_setRendered` cache in OneOfRule / NoneOfRule / ScanWhileRule / ScanUntilRule (set at construction with `set.ToString()`) keeps the pre-projection rendering, so trace messages show the user's typed entries rather than the post-Compile entries. Trace-only, no parse-time impact, but it can confuse a grammar author reading a trace to debug a normalization mismatch. Tracked separately if it bites someone.
    - Cross-reference with the leaf-id pinned-SymbolId matrix in `z006-2026-05-07-leaf-id-pinned-symbolid-shortcut-skip.md` and pattern doc `p1nd-user-identification-gate-misses-one-of-multiple-paths.md`: that matrix covers the four leaf-emitting rules that share the `ResolveLeafId` rune-as-leaf-id shortcut (OneOf, NoneOf, AnyToken, WithinToken). ScanWhile and ScanUntil also emit leaves but bypass the shortcut entirely (one leaf per run of multiple tokens, no single rune to use as the id), so they read the rule's `Id` directly and correctly honor `.As(SymbolId)` by construction without consulting `IsUserSymbolIdPinned`. After the post-merge update, two parallel tests (`ScanWhile_with_pinned_SymbolId_uses_pinned_id_for_run_leaf`, `ScanUntil_with_pinned_SymbolId_uses_pinned_id_for_body_leaf`) round out the test matrix to all six leaf-emitting rules so a future leaf-id refactor that routes the run-shaped rules through ResolveLeafId or a similar helper has to keep `.As(SymbolId)` working.
