- 2026-05-29: DisplayEscape escaped controls and line separators but leaked unpaired surrogate halves raw
    - Random pick: 59487 mod 28 = 15 over the 28 top-level `.cs` files under `src/InductorParser/` (alphabetical, skipping subdirectories) landed on `ParseCancellation.cs`. That file was clean for Unicode-specific behavior, so the sweep followed the scanner / public-lexer thread already active in the workspace: `Lexer.cs`, `Lexer.Scanning.cs`, `Token.cs`, `SurrogateHelpers.cs`, `ScanWhileRule.cs`, `ScanUntilRule.cs`, the external `ScanRunRule` helper, and the display/error surfaces that quote scanned text.
    - Reviewed prior Unicode hunt coverage for surrogate lookahead, multi-rune `NoneOf`, normalization leaks, scanner budget loops, raw control characters in traces / error messages / tree rendering, and TokenSet lone-surrogate membership. Avoided re-filing those fixed shapes. The fresh gap was paired-vs-unpaired surrogate rendering in the shared `DisplayEscape` helper.
    - Found and fixed: `DisplayEscape.AppendEscaped` and `DisplayEscape.Escape` only escaped Unicode categories Cc / Zl / Zp. That preserved valid surrogate pairs for supplementary-plane emoji, but it also preserved a lone high or low surrogate raw. Under `Compile(null)`, a parse failure at a lone surrogate made the `{character}` placeholder embed an unpaired UTF-16 code unit directly in `ParseResult.ErrorMessage`. Traces and long-form `PrintTree` had the same helper-level vulnerability. Fix: make the helper context-aware, preserving high+low surrogate pairs as pairs while rendering any unpaired surrogate code unit as `U+XXXX`.
