    - Found and fixed: when `ParseBudgetExceeded` throws while a lookahead `Probe` is open (Peek, Not, ScanUntil's rule-stopper, ScanUntil's escape-start), the throw unwinds through `Lexer.Probe.Dispose`, which restores the failure tracker, the subtree extent, and the position to the values captured at probe open. The catch handler in `Rule.ParseRecursive` then reads `lexer.DeepestFailure` and `lexer.Position` to compute `abortRaw` for the `ParseResult.Aborted` it returns. After the probe's restoration, both are at the pre-probe values, so `abortRaw` collapses to whatever shallow position the lookahead opened at (often 0). The user-visible `result.ErrorCharIndex` loses every diagnostic about how far the probe explored. Pre-refactor the OLD `using var transaction = lexer.BeginTransaction()` + separate `RestoreFailureState` / `DiscardSubtreeExtent` statements only restored the failure tracker on the normal-exit path: an in-flight exception jumped past those statements straight to the transaction's Dispose, which only rolls back the position, leaving the failure tracker intact for the catch handler to read. Repro: `Peek(recursive grammar)` with `MaxDepth = 50` reports `ErrorCharIndex = 0` post-refactor, `ErrorCharIndex = 16` pre-refactor. Fix moves the deepest-position computation to throw time: `ParseBudgetExceeded` carries an `int DeepestPositionAtAbort`, `Lexer.ThrowBudgetExceeded` computes `Math.Max(DeepestFailure, _position)` and embeds it before throwing, and the catch handler reads `budget.DeepestPositionAtAbort` instead of recomputing from the post-unwind lexer state. Regression test `Aborted_result_keeps_deepest_progress_when_budget_trips_inside_a_lookahead_probe` in `BudgetTests`.
    - Cleared: the normal success / failure paths' interaction between `Rule.TryParse`'s outer transaction and the new `Probe` was traced for Peek, Not, ScanUntil's three probe sites, Alias, And, BetweenInclusive, Or, and is equivalent to the OLD code: the `_subtreeDeepestFailure` ends at the same value after both OLD and NEW (the OLD `BeginTransaction` + `DiscardSubtreeExtent` + `Dispose` merge and the NEW `BeginProbe` + `Dispose` restore both reach the value present before the probe opened). The `Forced` flag handling in `WithinTokenRule`'s sub-lexer surface check (via the new `DeepestFailureIsForced` property) is equivalent. `OpensTransaction = false` for `EofRule` and `LateBoundRule` is sound because neither moves the cursor under a path that needs rollback. The `OpensTransaction` field-initializer order (default `true`, set `false` in EofRule / LateBoundRule constructors) was verified against C# instance initialization rules.
