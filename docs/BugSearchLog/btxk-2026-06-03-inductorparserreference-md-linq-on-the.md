    - Found and fixed (doc bug, not engine): InductorParserReference.md's "The Symbol Tree" + "LINQ on the Symbol Tree" sections had THREE references to APIs that don't exist (all in the same neighborhood, none backed by a test). (1) The API-surface code block declared `public IReadOnlyList<Symbol> FlattenInto();    // convenience overload`, but the real list-returning method is `Flatten()` (the only `FlattenInto` is `public void FlattenInto(List<Symbol> result)`). That wrong declaration is what seeded the example. (2) The LINQ "Flattened tree as a list" line read `symbol.FlattenInto().OfType<Symbol>()`, which gives CS7036 (no argument for required `result`) plus CS0023 (operator `.` on void), confirmed by compiling the doc-faithful snippet as a test and watching the build fail with exactly those two errors. (3) The LINQ "pre-order walk" line read `symbol.Walk().Where(s => s.Id == BuiltinSymbols.Integer)`, but `BuiltinSymbols` exists nowhere in the source (grep of the whole tree returns only this doc). `Integer()` is an anonymous composite that gets a custom-range id at Compile, so there's no stable built-in id to compare against, and the idiomatic form is a rule reference. (1) and (2) are the SAME bug the 2026-06-03 primer2 find fixed, in a second doc the primer2 pass didn't touch.
