- 2026-06-03: default(ParseResult) reported Success == true (fixed)
    - Random start: picked 47, 47 mod 29 = 18 (0-based) over the top-level `src/InductorParser/` `.cs` files → ParseResult.cs, which is where the bug ended up living. User steer: "focus on security and predictability" and "just focus on the recursive engine" (so the StateMachine experimental engine in ExperimentalSrc/ was out of scope).
    - The bug: `ParseOutcome.Success` is the enum's zero value, so a default-constructed `ParseResult` has `Outcome == Success`. `ParseResult.Success` was defined as `Outcome == ParseOutcome.Success`, so `default(ParseResult).Success` returned `true` while `Tree` was null and `Symbols` was empty. The everyday ways a default `ParseResult` shows up are real: an unassigned field, a `new ParseResult[n]` element, `List<ParseResult>.FirstOrDefault()` on an empty list, a `Dictionary` lookup miss / `GetValueOrDefault`. The idiomatic `if (result.Success) Use(result.Tree)` then treats a never-run parse as a successful one and NREs on `Tree` (or silently processes empty `Symbols`). That's a silent false-positive that a validation gate can wave through. The existing `ErrorPositionTests.Default_struct_does_not_throw_on_derived_property_read` shows the team already cared about default-struct safety (it asserts the derived position props coalesce to 0) but had overlooked `Success`, which confirms this was an oversight, not intent.
    - Fix: `ParseResult.Success => _grammar != null && Outcome == ParseOutcome.Success`. Every real result is built through `Succeeded` / `Failed` / `Aborted`, each of which stamps the grammar, so a null grammar means "never parsed." Minimal, non-breaking (didn't shift the public `ParseOutcome` numeric values). Regression test `ErrorPositionTests.Default_struct_does_not_report_success` (default, array element, and `FirstOrDefault()` all assert `Success == false`, with Tree/Symbols/ToString staying consistent). Verified: test fails before the fix (`Expected False, was True`) and passes after, full suite 7127 passed / 0 failed.
    - Pattern doc added: `PotentialBugSources/default-struct-enum-discriminator-defaults-to-a-meaningful-positive-state.md` (the silent-false-positive cousin of the existing reference-field-on-a-default-struct NRE pattern).
