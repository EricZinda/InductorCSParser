    - Bug found + fixed: the `AliasRule` parse-time / post-hoc-Flatten symmetry (tested by `AliasRuleTests.Alias_over_a_leaf_inner_flattens_back_to_the_default_tree` and the Flatten-inner sibling, plus pattern doc `PotentialBugSources/evzz-*`) breaks when the alias wraps a Delete inner. Default parse: the Delete inner returns `Symbol.Discarded`, so a Preserve (named) alias around it is empty. Under `PreserveAllSymbols` the flag forces the inner to act Preserve, so it returns a real Symbol. `AliasRule.TryParseRule`'s content-build `else if (!ReferenceEquals(innerSymbol, Discarded))` branch then lifts the Delete inner's children (or adds the Delete leaf), and post-hoc `Flatten()` keeps them, so the collapsed debug tree has content the default parse dropped. Reproduced via the public API with `Or(Token('c').Preserve(), Token('b').Preserve()).Flatten(FlattenType.Delete).AliasedAs("ROOT")` (default ROOT empty, PreserveAll+Flatten ROOT has 'c') and the realistic `InlineWhitespace().AliasedAs("ws")`. Fixed by adding `&& _inner.FlattenType != FlattenType.Delete` to that branch's condition, mirroring the same term already in the `EmitsLeaf` check, so a Delete inner contributes nothing in both modes.
    - The existing symmetry tests covered a leaf inner and a Flatten-leaf inner but not a Delete composite/leaf inner, which is exactly the gap that let this through. Added `AliasRuleTests.Alias_over_a_Delete_inner_flattens_back_to_the_default_tree` and `..._Delete_leaf_inner_...` (fail pre-fix, pass post-fix). Full suite green: recursive 6963 passed, statemachine AliasRuleTests 49 passed.
    - Note for the next hunter: this is a fresh instance of the `evzz` "parse-time vs post-hoc Flatten symmetry" pattern, the prior instance (b4xv) being the Flatten-leaf case. The recurring trap is that `PreserveAllSymbols` makes every inner return a real Symbol instead of `Discarded`, so any rule that branches on `ReferenceEquals(x, Symbol.Discarded)` to decide "inner contributed nothing" misclassifies a Delete inner under the flag. Audited the other composites (And, Or, BetweenInclusive): they KEEP the inner Symbol as a child rather than lifting, so post-hoc Flatten re-applies the inner's Delete correctly, whereas only AliasRule lifts, which is why only it was affected.
