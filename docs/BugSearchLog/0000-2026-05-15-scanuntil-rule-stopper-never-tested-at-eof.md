    - Categories: Rule-stopper vs TokenSet-stopper parity in `ScanUntilRule`, EOF-sensitive stopper rules (`Eof()`, `Not(AnyToken())`, `Or(..., Eof())`), loop-bound `while (!lexer.IsEof)` exiting before a final EOF-position check, `set & Universe` dropping multi-rune entries (verified intentional — `Universe` is rune-only by definition), `Combine` mixed-polarity `N \ P_runes` soundness (verified a subset of the true fail-set, sound), `LookaheadFirstRunes` lone-surrogate first rune (verified unreachable — `Graphemes()` rejects lone-surrogate-leading clusters), `GraphemeClusterIndex.EnsureWalkedTo` monotonic-enumerator correctness, `BuildErrorMessage` `{character}` placeholder vs `failurePos == input.Length` (verified the canonical and compat position-map walkers never return `input.Length` while `posInParseInput < parseInput.Length`).
    - Found and fixed: `ScanUntilRule.TryParseRule`'s scan loop is `while (!lexer.IsEof)` and the Rule-stopper is only tested inside that loop, so it is never tested at the EOF position itself. A stopper rule that matches at end of input — `Eof()`, `Not(AnyToken())`, `Or(Literal("END"), Eof())` — is never recognised there, and strict `ScanUntil` falls into the `!stopperMatched && !_eofIsTerminator` failure branch. `ScanUntil(Eof())` always fails even though it reads as "scan until end of input" and `ScanUntilEof()` (implemented via the TokenSet path with `eofIsTerminator: true`) succeeds on the same input. The fix adds a single post-loop check: when the loop exited at EOF (`lexer.IsEof`), `!stopperMatched`, strict (`!_eofIsTerminator`), and the stopper is a rule (`_stopperRule != null`), run the stopper once more in a peek transaction at the EOF position. Gated so the TokenSet path and the non-EOF `break` exits (escape zero-width, body-bounds) are untouched; a normal Rule-stopper like `Literal("X")` still fails at EOF (reads the EOF token) so strict failure on a genuinely-never-matching stopper is unchanged.
