    - Found and fixed (p1nd): the four rules' shared leaf-id line `leafId = (Name == null && runeValue >= 0) ? new SymbolId(runeValue) : Id` only checks `Name`, missing the `.As(SymbolId)` pin. A grammar like `OneOf(letters).As(new SymbolId(MyId)).Parse("a")` produced a leaf with `Id == 0x61` (the rune 'a') instead of `MyId`, so `Tree.Find(rule)` and `Tree.Is(rule)` returned null / false. Multi-rune branches were unaffected because `runeValue == -1` already short-circuits to `Id`. Documented use case for `.As(SymbolId)` is stable serialized-parse-tree numbering (per `Rule.As(SymbolId)` doc), so the silent loss of the pinned id is a real bug for that workflow.
    - The fix consults the existing `IsUserSymbolIdPinned` accessor (added by the xpid fix on master). All four rules' leaf-id line becomes `(Name == null && !IsUserSymbolIdPinned && runeValue >= 0) ? new SymbolId(runeValue) : Id`. The truly-anonymous-rule optimization (no `.As(string)`, no `.As(SymbolId)`) is preserved, and the gate now honors both user-identification paths symmetrically. Four regression tests, one per affected rule (`OneOfRuleTests`, `NoneOfRuleTests`, `AnyTokenRuleTests`, `WithinTokenRuleTests`), each pinning a distinct custom-range id and asserting `Tree.Id == pinnedId`, `Tree.Is(rule)`, and `Tree.Find(rule)`.
