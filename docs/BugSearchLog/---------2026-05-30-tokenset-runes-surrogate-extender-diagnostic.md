    - Found and fixed: `TokenSet.Runes(string)` asked `StringInfo.GetNextTextElement` for the next grapheme and checked `grapheme.Length != consumed` before validating that the current code unit decoded to a valid Unicode scalar. On .NET 8, a lone surrogate followed by an extender such as U+0301 can be treated as one text element, so `TokenSet.Runes(HighSurrogate + U+0301)` threw the "multi-rune grapheme cluster" message. That message points users at `TokenSet.Graphemes(...)`, but the input contains a lone surrogate, so `Graphemes(...)` would also reject it. Fix: validate `Rune.IsValid(rune)` before the multi-rune grapheme check so malformed UTF-16 wins with the invalid-scalar message.
