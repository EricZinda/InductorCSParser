    - Found and fixed (z0bh):
        1. `LateBoundRule.Bind(target)` in `src/InductorParser/LateBoundRule.cs` had no guard against a second call before Compile. The first call sets `_target` and calls `SetChildren(target)`. The second call silently overwrites both. The grammar runs against whichever target initialized last with no error pointing at the duplicate `Bind`. Same shape as the `.As(string)` / `.As(SymbolId)` / `.WithError(...)` set-once bugs fixed in commit 6daadb1 (which left `.Bind` alone — almost certainly an oversight, not a design decision). The 2026-05-08 bug-search log noted this as "allowed by design; only `_sealed` blocks rebinding" but the recent set-once sweep changed the project's stance on mutate-in-place identification methods.
       Fix shape: add `if (_target != null) throw new InvalidOperationException(...)` right after the existing null-check, matching the `As(string)` / `As(SymbolId)` / `WithError` set-once error-message shape. The pre-existing `Bind_after_compile_throws` still passes because its second `.Bind` call now throws via the "already bound" path before reaching the seal check inside `SetChildren`.
