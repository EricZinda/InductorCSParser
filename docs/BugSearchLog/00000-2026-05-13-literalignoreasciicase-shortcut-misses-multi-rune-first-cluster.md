    - Categories: lookahead-shortcut soundness (sets that don't reflect what the rule actually consumes), case-insensitive matching gaps, Compile-form interaction with cached `FirstConsumedTokens`, ASCII-letter handling that drops on its multi-rune-cluster path.
    - Cross-checked `LiteralIgnoreAsciiCaseRule.ComputeRuleStart` against the parse-time behavior: `AsciiCaseEquals` happily case-folds the ASCII-letter half of a multi-rune cluster (the e/E pair in "é" / "É" after FormD decomposition), but the shortcut's set only carried the cluster in its original case. The existing tests cover the precomposed-FormC happy path and don't exercise the FormD-decomposed-first-cluster shape.
    - Found and fixed (`z0ci`): `LiteralIgnoreAsciiCase("éclair").Compile(NormalizationForm.FormD)` rewrites `_expected` to `"éclair"` (decomposed), and `ComputeRuleStart` then publishes `FirstConsumedTokens = TokenSet.Graphemes("é")`. For input `"Éclair"` (FormD-decomposed to `"Éclair"`), the peek cluster is `"É"` and `CannotMatchLookahead` returns `true` (neither the first-rune check nor the strict cluster check matches a `TokenSet` whose only entry is the lowercase-half cluster). `Or(LiteralIgnoreAsciiCase("éclair"), fallback).Compile(FormD).Parse("Éclair")` and `OneOrMore(LiteralIgnoreAsciiCase("éclair")).Compile(FormD).Parse("Éclair")` both fail, even though running the case-insensitive branch would have matched. Fix extends the ASCII-letter branch of `ComputeRuleStart` to cover `firstElement.Length >= 1`: both case variants of the first rune go into the set as rune intervals, and the original cluster goes in as a multi-rune entry. Two regression tests in `src/InductorParser.Tests/Rules/LiteralIgnoreAsciiCaseRuleTests.cs` lock in the Or-shortcut and the BetweenInclusive-shortcut paths.
    - Adjacent shape (not pursued): no other rule has runtime case-folding semantics, so the "first-token set lies about which inputs the rule will actually match because of a runtime case-fold" pattern is specific to `LiteralIgnoreAsciiCaseRule`. The general pattern ("static analysis publishes a tighter set than the rule's runtime predicate") is the broader category. Added to `docs/PotentialBugSources/`.
