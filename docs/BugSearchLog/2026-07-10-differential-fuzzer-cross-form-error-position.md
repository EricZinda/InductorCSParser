- Differential grammar fuzzer campaign, and the cross-form error-position find
    - Method: instead of a per-file read, this hunt built the differential grammar fuzzer from backlog 0a01 and ran it as a scratch harness. Random grammar blueprints over the public factories (And, Or, Optional, ZeroOrMore, OneOrMore, Exactly, Token including grapheme Tokens, Literal, LiteralIgnoreAsciiCase, OneOf, NoneOf, ScanWhile, ScanUntil in set, eof, escape, and rule-stopper forms, AnyToken, Eof, EndOfLine, Not, Peek, Alias, WithinToken, LateBound recursion, with .As / .Flatten / .Delete / .WithError modifiers), grammar text drawn from the UnicodeExamples corpus by reflection, inputs biased toward each grammar's terminals plus canonically recoded and ill-formed variants.
    - Oracles: parse-twice determinism, Compile(FormC) vs Compile(null) on NFC input, Compile(FormC) vs Compile(FormD) on any input (skipped for WithinToken grammars, whose rune-level inners are form-sensitive by design), unnamed-Alias-wrap neutrality, PreserveAllSymbols round-trip via Symbol.Flatten, and SourceText / SourceRange agreement against the original input.
    - Volume: about 5.3 million ASCII-grammar cases (level 1) and 2.7 million Unicode-corpus cases (level 2), roughly 670K successful parses total exercising the tree oracles.
    - Clean categories: determinism, FormC-vs-null, alias-wrap neutrality (trees and error reports), debug round-trips, SourceText / SourceRange agreement, and all success-path FormC-vs-FormD tree comparisons. Also swept by hand this round with nothing found: TokenSet set algebra (3000-trial randomized property test), ScanUntilRule, WithinTokenRule, BetweenInclusiveRule, NotRule, NormalizedPositionMap, SourcePositionConverter, and the f7aab85 alias rework (differential matrix over seven inner shapes, three alias treatments of no alias / transparent / named, two modes).
    - The find: failing parses reported different ErrorCharIndex, and sometimes a different message kind, depending on the compile normalization form. Root cause: LiteralRule and GraphemeRule counted failure progress in runes of their expected text, so a partially matched multi-rune grapheme counted as progress, and rune counts differ across canonical forms. Also visible in a single form with clusters that have no precomposed shape (Literal("q̣̇") on "q̣" said "unexpected end of input" instead of pointing at the mismatched character).
    - Fixed by counting failure progress in whole graphemes of the expected text: GraphemeRule records at the attempt start (its expected text is one grapheme), LiteralRule floors the matched-char count to a grapheme boundary of the expected string. Regression tests live in LiteralRuleTests and GraphemeRuleTests. Backlog 0a00 documents the runbook.
    - For the next hunter: the fuzzer harness is worth institutionalizing per backlog 0a01. The strict flag arms the FormC-vs-FormD error comparison, which is the oracle that found this.
