- 2026-05-07: TokenSet.ContainsToken NREs on default(TokenSet) with multi-rune token input
    - Random-pick area: started from a random number against the `src/InductorParser/*.cs` listing (24 → `TokenSet.cs`), and read it side-by-side with `OneOfRule.cs`, `NoneOfRule.cs`, `ScanUntilRule.cs`, `Rule.cs` (`CannotMatchLookahead`, `FirstConsumedTokens`), `RuleStartRequirements.cs` (`NeverAdvances`, `MatchesAnyOf` / `MatchesAllOf` empty-children paths, `Combine` with `TokenSet.Empty`), `Lexing/Lexer.FastPaths.cs` (the scanner-skip caller of `ContainsToken`), and the existing `TokenSetTests` (`Default_TokenSet_is_empty`, `Union_with_default_TokenSet_returns_the_other_side`).
    - Categories: `default(TokenSet)` field-state vs. constructor-coalesced field-state, public `TokenSet.Empty` aliasing `default`, every method on the struct that reads `_multiRuneGraphemes` directly vs. through an existing null-coalescing accessor, parallel between `Contains(int)`'s null-guarded `_ranges` read and `ContainsToken`'s unguarded `_multiRuneGraphemes` read, surfaces in OneOf / NoneOf / ScanUntil / Lexer.FastPaths / Rule.CannotMatchLookahead.
    - Found and fixed (tsne): `TokenSet.ContainsToken(ReadOnlySpan<char>)` line 172 reads `_multiRuneGraphemes.Length` directly. The 2-arg constructor coalesces null to `Array.Empty<string>()`, so every TokenSet built by the public factories (`Single`, `Range`, `Runes`, `Category`, the `|` / `&` / `~` operators, `NormalizedFor`, `WithCompatibilityEquivalents`) has a non-null array. But `default(TokenSet)` skips the constructor, leaves `_multiRuneGraphemes` null, and is the value behind the public `TokenSet.Empty` constant. A user-facing rule like `OneOf(TokenSet.Empty)` or `NoneOf(TokenSet.Empty)` reads `_set.ContainsToken(token.Chars)` at parse time. When the next token is a multi-rune grapheme that isn't a surrogate pair (decomposed `é` as `e + combining acute`, ZWJ family emoji, regional-indicator flag, CRLF), `TrySingleRune` returns false and the unguarded `_multiRuneGraphemes.Length` read throws NullReferenceException. The user gets an unhandled exception bubbling out of `Parse`, not a parse failure. Backlog `tsne` has the write-up.
    - The fix caches `_multiRuneGraphemes` to a local and null-checks it before the `.Length` read, matching the cache-to-local-and-null-check shape `Contains(int codepoint)` already uses for `_ranges`. Fix is in TokenSet, so every caller benefits without changes. Two regression tests: `NoneOf_with_TokenSet_Empty_admits_a_multi_rune_grapheme_without_NRE` and `OneOf_with_TokenSet_Empty_rejects_a_multi_rune_grapheme_without_NRE`. Full suite: 4645 / 4647 (2 pre-existing timing-grammar skips) at the baseline, 4647 / 4649 with both new tests and the fix in place.
    - Sibling check: `Contains(int)` already null-coalesces (`var ranges = _ranges; if (ranges == null) return false;`); `MultiRuneGraphemes` accessor (line 122-123) already null-coalesces (`_multiRuneGraphemes ?? Array.Empty<string>()`); `BinarySearchMultiRune` already null-checks (`if (array == null || array.Length == 0) return ~0`). `Equals`, `GetHashCode`, `IsEmpty`, `ToString`, `HasMultiRuneGraphemes` all read length-or-null safely. `EnumerateRunes` null-checks `_ranges`. `RunesOnlyPart` and `LookaheadFirstRunes` only inspect `HasMultiRuneGraphemes`, which is null-safe. `NormalizedFor` and `WithCompatibilityEquivalents` null-check both fields before iteration. So `ContainsToken` was the only entry point on the struct that wasn't null-safe against `default(TokenSet)`, and the fix closes that single gap.
    - Cross-cutting note: this is the same shape as `Contains(int)`'s null-guard pattern (cache to local, null-check, then read). The pre-existing `MultiRuneGraphemes` accessor and the `BinarySearchMultiRune` helper both follow the pattern; `ContainsToken` was an outlier. Pattern doc `tsne-public-default-struct-with-non-coalesced-field.md` describes the broader pattern (a `readonly partial struct` exposing a public `default`-aliased constant where one or more reference-typed fields are coalesced only by the constructor, so `default(T)` reads the field as null while every factory-built T reads it as `Array.Empty<...>()`).
