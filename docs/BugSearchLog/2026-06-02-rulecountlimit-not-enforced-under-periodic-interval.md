    - Candidate that turned out NOT to be a bug: `ParseOptions.RuleCountLimit` is enforced only inside `ParseBudget.CheckPeriodicBudgets`, which runs every 1024 rule invocations (`BudgetCheckInterval`), so a parse finishing in fewer than 1024 invocations never trips a small RuleCountLimit (e.g. `OneOrMore(OneOf(Digits)).Parse("1234567890", RuleCountLimit=5)` returns Success). This is the same 1024-granularity the wall-clock `Timeout` rides, and it's by design for the same reason: the budget is a runaway/DoS valve, and a parse short enough to finish before the first periodic check is trivially fast and harmless. (Confirmed by the maintainer.) The asymmetry with `MaxDepth` (which IS checked exactly on every EnterRule) is intentional: exceeding MaxDepth risks a real, uncatchable StackOverflowException, so it has to be exact, whereas overrunning a coarse rule-count cap by up to 1024 invocations is harmless.
