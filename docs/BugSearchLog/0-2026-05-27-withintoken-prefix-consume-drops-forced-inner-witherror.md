- 2026-05-27: WithinToken's prefix-consume branch drops the inner's forced .WithError (asymmetric with the inner-failed branch's transfer)
    - Trail: after the morning's clean sweep ([0-2026-05-27-literalignoreasciicase-and-post-refactor-lexer-files-clean.md](0-2026-05-27-literalignoreasciicase-and-post-refactor-lexer-files-clean.md)) the user asked for fresh angles. Re-read [WithinTokenRule.cs](../../src/InductorParser/WithinTokenRule.cs) noting the two failure branches: (a) inner failed outright, (b) inner succeeded but consumed only a prefix of the outer cluster. The 2026-05-18 fix to branch (a) transfers `subLexer.DeepestFailureMessage` with the inner's forced flag preserved. Branch (b) was never updated for the same fix. Checked the [pattern doc](../PotentialBugSources/0000-2026-05-18-sub-lexer-failure-transfer-drops-the-forced-flag.md) which already names the broader pattern: "any time code reads one Lexer's DeepestFailureMessage and re-records it on another Lexer, the forced argument has to be the message's own forced status." Branch (b) silently violated this rule by recording only WithinToken's own ErrorMessage and dropping the sub-lexer's deepest message entirely.
    - Found and fixed: a grammar like `WithinToken(Or(Literal("ex").WithError("expected ex", forced: true), AnyToken()))` parsing the decomposed e-acute cluster ("e" + U+0301, one grapheme, two runes) matches the Or via the `AnyToken` fallback on the first rune and leaves the combining acute unconsumed. WithinToken hits branch (b) ("inner consumed only 1/2 of the token") and silently dropped the forced "expected ex" message that the rejected Literal alternative recorded in the sub-lexer's forced slot. The user-visible error became the generic mechanical "unexpected 'é'" message at offset 0 instead of the user's chosen forced hint. The forced flag is the user's explicit "surface this message" override, and branch (b) effectively erased it whenever a fallback alternative shaved off a prefix.
    - Fix: added the same `subLexer.DeepestFailureMessage` + `forced: subLexer.DeepestFailureIsForced` transfer the inner-failed branch already does, recorded before WithinToken's own ErrorMessage so depth-primary ranking picks the winner. Mirrors the inner-failed branch's structure exactly and keeps the prefix-consume-vs-inner-failed asymmetry from being a hidden information-loss path.
    - Verified failing-then-passing with two regression tests added next to the existing prefix-consume tests in [WithinTokenRuleTests.cs](../../src/InductorParser.Tests/Rules/WithinTokenRuleTests.cs): `Forced_inner_WithError_surfaces_when_WithinToken_fails_on_prefix_consume` covers the forced case, and `Named_inner_WithError_surfaces_when_WithinToken_fails_on_prefix_consume` covers the non-forced case (the same code path handles both, since the transfer preserves whatever forced flag the inner message had). Both fail on master before the fix with `Expected: "expected ex" But was: "Parse failed at offset 0: unexpected 'é'."` and pass after. The full WithinTokenRuleTests fixture runs 127 / 127, the recursive test suite runs 6856 / 0 / 2 skips, the StateMachine test suite runs 108 / 1 / 0 (the pre-existing `LiteralIgnoreAsciiCase_does_not_fold_non_ascii` was broken before this commit and is acknowledged in 380ed79's commit message).
