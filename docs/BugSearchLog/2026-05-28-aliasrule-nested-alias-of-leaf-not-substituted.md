- 2026-05-28: AliasRule of an alias of a leaf no longer substitutes (the nested alias wraps the inner alias's leaf in an extra composite and leaves the inner alias's identity findable)
    - Focus: bugs introduced in recent changes (user-directed). Reviewed the most recent source commits: bbb7d16 (AliasRule leaf substitution / new Rule.EmitsLeaf property) and e429d76 (widen Rule access modifiers for external subclasses). bbb7d16 touched 28 files to add a `Rule.EmitsLeaf` property set explicitly at every base ctor and routed AliasRule's leaf-substitution decision through it instead of the runtime `innerSymbol.IsLeaf`. That refactor is where the regression landed.
    - Files reviewed: `AliasRule.cs` (full), `Rule.cs` (new EmitsLeaf property + ctor), `LateBoundRule.cs` (EmitsLeaf forwarding), and the `emitsLeaf:` argument at every `base(...)` call across the 17 rule files (AndRule, OrRule, AnyTokenRule, BetweenInclusiveRule, GraphemeRule, EofRule, LiteralRule, LiteralIgnoreAsciiCaseRule, NoneOfRule, NotRule, OneOfRule, PeekRule, ScanUntilRule×6, ScanWhileRule, WithinTokenRule). All 17 leaf/composite/zero-width emitsLeaf values are correct. The miss is AliasRule itself: it hardcodes `emitsLeaf: false` in its ctor and (before this fix) had no override.
    - Bug: AliasRule's new substitution gate reads `_inner.EmitsLeaf` (a static rule-level property) to decide whether to substitute the alias's identity onto a leaf inner. The old code read the runtime `innerSymbol.IsLeaf` of the value the inner returned. An AliasRule that substitutes does return a leaf at runtime, but its declared `EmitsLeaf` was hardcoded `false`. So `leaf.AliasedAs("a").AliasedAs("b")` (which nests two AliasRules, since AliasedAs = `new AliasRule(this).As(name)`): the outer alias asks the inner alias's EmitsLeaf, gets false, skips substitution, and wraps the inner alias's leaf in an extra composite. Two visible consequences vs a single alias of the leaf: the tree gains a nesting level, and `result.Find(innerAlias)` is non-null, so the inner alias's identity isn't hidden, breaking AliasRule's documented tenet ("an alias's Symbol behaves like the inner's Symbol would, except for its identity"). The differential fuzzer (regular vs PreserveAllSymbols+Flatten) doesn't catch this because the new code is static, so both capture modes now agree with each other (both wrong). They only diverge from the pre-refactor behavior.
    - Verify: `Rules/AliasRuleTests.cs` test `Alias_of_alias_of_leaf_substitutes_to_a_single_leaf`. `OneOf(TokenSet.Digits).AliasedAs("inner").AliasedAs("outer").Parse("5")` asserts the tree is a single leaf carrying "5", `Find(innerAlias)` is null, and `Children` is empty. Fails before the fix (`Find(innerAlias)` returns `<5>`), passes after.
    - Fix: gave AliasRule an `EmitsLeaf` override mirroring its substitution gate (`_inner.EmitsLeaf && FlattenType == Preserve && _inner.FlattenType != Delete`) and routed TryParseRule's gate through that same property so the two can't drift. Now an alias that substitutes reports EmitsLeaf=true, so a parent alias substitutes too and the nest collapses to one leaf. Full suite green (6935 pass, 2 skip), solution builds clean including InductorParser.ExternalContractTests.
