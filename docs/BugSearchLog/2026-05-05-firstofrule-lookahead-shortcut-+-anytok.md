- 2026-05-05: OrRule lookahead shortcut + AnyToken / lone-surrogate sweep
    - Reviewed: `OrRule.cs`, `BetweenInclusiveRule.cs` (for comparison), `AndRule.cs`, `AnyTokenRule.cs`, `EofRule.cs`, `PeekRule.cs`, `NotRule.cs`, `Rule.CannotMatchLookahead`, `RuleStartRequirements.cs`, `TokenSet.Universe.Contains`, `Lexer.TryPeekRune`.
    - Cross-checked every caller of `CannotMatchLookahead` (OrRule + BetweenInclusiveRule) for the discard-the-bool-return shape, and audited the other 11 `TryPeekRune` call sites for the same pattern.
    - Categories: EOF vs lone-surrogate conflation in lookahead shortcuts, AnyToken-fallback wildcard handling on surrogate-prefixed input, Or-vs-BetweenInclusive shortcut divergence, `Universe.Contains(-1)` sanity.
    - Found and fixed: `OrRule.TryParseRule` discarded `Lexer.TryPeekRune`'s bool return and let a lone-surrogate `peekValue = -1` reach `CannotMatchLookahead`, which wrongly skipped `Advance.Always` children whose `FirstConsumedTokens` is `Universe` (notably `AnyToken()`). Under `Compile(null)` this broke `Or(specific, AnyToken())`-style grammars on surrogate-prefixed input even though the wildcard fallback would have matched the surrogate as a one-char token. `BetweenInclusiveRule` already handled this correctly by short-circuiting on the bool return (`&& Lexer.TryPeekRune(...)`); the fix mirrors that. Backlog 5kf2 has the full write-up.
    - Two regression tests in `UnexpectedUnicodeTests` lock in the high- and low-surrogate shapes; a third pinning test confirms the EOF half of the shortcut still fires after the fix.
