- 2026-05-05: parse-tree leaf Id assignment + NameOf sweep
    - Reviewed every rule that emits a leaf Symbol AND the lookup path from a parse-tree SymbolId back to a name. Walked: `OneOfRule.cs`, `NoneOfRule.cs`, `AnyTokenRule.cs`, `WithinTokenRule.cs`, `LiteralRule.cs`, `LiteralIgnoreAsciiCaseRule.cs`, `GraphemeRule.cs`, `ScanWhileRule.cs`, `ScanUntilRule.cs`, `Rule.NameOf`, `Rule.CollectNames`, `SyntaxTree/SymbolExtensions.PrintTree`. Categories: leaf Id assignment, `Tree.Find(rule)` and `Tree.Is(rule)` consistency across single-rune vs. multi-rune outer tokens, alignment of leaf Id with the rule's `.As("name")` user expectation, behavior of `result.NameOf(leaf.Id)` and `PrintTree` on character-range ids.
    - Found and fixed (two places, same shape):
        - `OneOfRule`, `AnyTokenRule`, `NoneOfRule`, and `WithinTokenRule` all used the matched rune's code point as the leaf Id when the outer token was one rune, falling back to the rule's own Id only when the outer token was multi-rune. So a named rule like `OneOf(letters).As("letter")` or `WithinToken(...).As("character")` emitted leaves with `Id == 0x61` for ASCII "a" but `Id == rule.Id` for multi-rune Devanagari "हि". Tree.Find / Tree.Is silently returned the wrong answer for the single-rune case.
        - `Rule.NameOf` had the same shape one level lower: it short-circuited any character-range id directly to the rune's text before consulting the name index. `GraphemeRule` (Rules.Token) writes its rune-codepoint Id as the rule's *own* Id at construction time, so `Token('a').As("aChar").Id` is `0x61` and lands in the character range. `result.NameOf(leaf.Id)` returned "a" instead of "aChar", and `PrintTree` rendered `'a'` instead of `aChar: "a"`. The user's `.As(...)` was silently swapped for the rune's text whenever the rule's Id landed in the character range.
    - The fix gates both rune branches on "is the rule user-named?", preserving the documented unnamed-rule defaults (rune-as-leaf-id for fast tree dispatch, rune-as-NameOf for compact PrintTree on character leaves) and honoring the user's `.As(...)` whenever set:
        - All four leaf-emitting rules now share the line `leafId = (Name == null && runeValue >= 0) ? new SymbolId(runeValue) : Id`.
        - `Rule.NameOf` consults the name index first; an entry with `IsUserSupplied == true` wins over the rune-text default. The name index now stores `(string Name, bool IsUserSupplied)` instead of just `string` so user names can be distinguished from the trace-name fallback (`And`, `OneOrMore`, `Token`, ...).
        - `SymbolExtensions.PrintTree` falls through to the long `<name>: "<text>"` form when a character-range leaf's `NameOf` returns something other than the rune's text, so a named single-rune Token shows up as `aChar: "a"` instead of `'aChar'`.
    - `LiteralRule` was already aligned: it always uses `Id` for the leaf and its rule Id is in the custom range, so NameOf consults the index normally.
