    - Found and fixed: `Lexer.AdvanceWhileRuneIn` (the rune-only fast path `ScanWhileRule` dispatches to) broke its run whenever `TryPeekRune` returned false. `TryPeekRune` returns false on a lone surrogate, so `ScanWhile(set)` stopped dead at a lone-surrogate token even when `set`'s rune intervals cover that surrogate's code unit (e.g. `ScanWhile(TokenSet.Range(0, 0x10FFFF))` under `Compile(null)`). `OneOfRule` tests membership with `TokenSet.ContainsToken`, whose lone-surrogate branch deliberately matches the surrogate by its UTF-16 code unit, so `ScanWhile` silently produced a shorter match than its documented equivalent `AtLeast(n, OneOf(set))`. Fix splits `AdvanceWhileRuneIn`'s membership test: a one-char lone-surrogate token now consults `set.Contains((int)theSurrogateChar)`, matching `ContainsToken`. `AdvanceWhileTokenIn` (the mixed-set path) already handled this correctly via `ContainsToken`.
