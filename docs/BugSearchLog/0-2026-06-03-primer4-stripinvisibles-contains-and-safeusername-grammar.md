    - Found and fixed in Primer4.md (two doc bugs, not engine):
        1. The "Invisible characters" StripInvisibles helper read `Invisibles.Contains(r)` where `Invisibles` is a `TokenSet` and `r` is a `Rune`. `TokenSet` has no `Contains` method at all (grep of the whole src returns none). The rune-membership test is `ContainsRune(Rune)` (TokenSet.cs:143), alongside `ContainsRune(int)` / `ContainsRune(char)` and `ContainsToken(string)` / `ContainsToken(ReadOnlySpan<char>)`. So the documented helper gives CS1929 (no `Contains` member on `TokenSet`), confirmed by compiling the doc-faithful snippet as a test and watching the build fail. Anyone copy-pasting the strip-invisibles recipe got a build error. This is another `aaaa` instance (doc naming an API that doesn't exist). The existing `SecurityByDefaultTests.Blocking_invisible_smuggling` test uses a `HashSet<int>` and `.Contains(int)`, so it never exercised the doc's `TokenSet` form and the drift went unseen.
        2. The "safe username" grammar read `And(OneOrMore(And(NoneOf(Invisibles), AnyToken())), Eof())` and the doc claims `Parse("admin").Success == true`. It's false. `NoneOf` consumes one non-invisible token per match, so pairing it with `AnyToken()` eats two tokens per iteration. On "admin" (5 tokens) the inner And matches "ad", "mi", then fails with no token left to pair with "n", OneOrMore stops at 2 (consumed "admi"), and Eof fails on the leftover "n". Odd-length all-visible input always fails. The `Not(stopRule) + AnyToken()` idiom is for the zero-width `Not` lookahead, not the consuming `NoneOf`. Correct grammar is `And(OneOrMore(NoneOf(Invisibles)), Eof())`, since `NoneOf(Invisibles)` already means "a token that isn't invisible". This was caught by the new regression test failing on `Parse("admin")` before the fix.
