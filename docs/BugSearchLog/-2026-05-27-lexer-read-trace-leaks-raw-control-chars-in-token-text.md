    - Found and fixed: `Lexer.Read` at [Lexer.cs](../../src/InductorParser/Lexing/Lexer.cs) builds its diagnostic trace as `$"'{_input.Substring(t.Offset, t.Length)}', Consumed: {_position}"`, splicing the raw token text into the line between single quotes. For any token whose text holds a Control (Cc), LineSeparator (Zl), or ParagraphSeparator (Zp) char (the CRLF cluster from `TokenSet.LineTerminators`, a `Token('\n').Preserve()` match, an LF / CR / VT / FF / NEL / LS / PS rune captured by `OneOf(LineTerminators)`), the verbatim splice dumps a real CR or LF inside the quotes and the one-event-per-line layout the rest of the trace machinery maintains breaks. Sibling render paths `TokenSet.ToString` (the 2026-05-20 fix) and `SymbolExtensions.PrintTree` (today's earlier fix) already escape these same categories. `Lexer.Read` had the same job and needed the same escape.
    - Fix: extracted the escape logic into a shared `DisplayEscape` helper at [src/InductorParser/Tracing/DisplayEscape.cs](../../src/InductorParser/Tracing/DisplayEscape.cs). It exposes `IsControlOrLineSeparator(char)`, `IsControlOrLineSeparator(int)`, `AppendEscaped(StringBuilder, ReadOnlySpan<char>)` for per-char accumulation, and `Escape(string, int, int)` for return-a-new-string callers (with a no-allocation fast path that scans once and falls back to plain `Substring` when no chars need escape). Routed all three render paths through it. `Lexer.Read` calls `DisplayEscape.Escape`, `SymbolExtensions.PrintTree`'s short form uses `DisplayEscape.IsControlOrLineSeparator(int)`, and `TokenSet.ToString`'s multi-rune append uses `DisplayEscape.AppendEscaped`. The three formerly-private helpers in those files (the local `IsControlOrLineSeparator` plus `AppendGraphemeForDisplay`) are deleted, so the rule lives in one place and the next caller that needs it doesn't add a fourth copy.
