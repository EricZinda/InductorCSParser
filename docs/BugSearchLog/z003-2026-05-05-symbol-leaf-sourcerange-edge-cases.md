- 2026-05-05: Symbol leaf SourceRange edge cases
    - Reviewed every rule that emits a leaf Symbol, asking which paths can produce a zero-width / empty leaf and whether `Symbol.SourceRange` reports a usable position for one. Walked: `src/InductorParser/SyntaxTree/Symbol.cs` (`SourceRange`, `FindFirstLeafWithText`, `FindLastLeafWithText`, `FlattenInto`, `Find`, `FindAll`, `Walk`, `GetUtf8ByteCount`), `SyntaxTree/SourcePosition.cs`, `SyntaxTree/SourcePositionConverter.cs`, `SyntaxTree/SymbolExtensions.cs`, plus every leaf-emitting rule: `OneOfRule.cs`, `NoneOfRule.cs`, `AnyTokenRule.cs`, `WithinTokenRule.cs`, `LiteralRule.cs`, `LiteralIgnoreAsciiCaseRule.cs`, `GraphemeRule.cs`, `ScanWhileRule.cs`, `ScanUntilRule.cs`, `EofRule.cs`, `PeekRule.cs`, `NotRule.cs`. Cross-checked the existing `SymbolPositionTests` fixture and its composite-empty-leaf coverage (`Empty_leaf_in_middle_does_not_truncate_composite_range`, `Trailing_empty_leaf_does_not_extend_composite_range`).
    - Categories: zero-width-leaf SourceRange, MemoryMarshal.TryGetString recovery from empty memory, FindFirstLeafWithText / FindLastLeafWithText skip-on-empty heuristic, ScanUntil zero-width body shape under Preserve, position-recovery for highlighting / offset-readback consumers, lone-surrogate handling in Token.RuneValue.
    - Found and filed (0srg): `Symbol.SourceRange`'s top-level call to `FindFirstLeafWithText` returns null when the receiver IS a standalone empty leaf, because the helper's skip-on-empty branch fires on the receiver itself. ScanUntil with the stopper at the cursor produces exactly that shape: a Symbol whose `_leafChars` is `input.AsMemory(N, 0)`. The memory still carries the source string and offset N (TryGetString recovers both), so the position is reachable; the IsEmpty short-circuit just throws it away. User-visible canonical case: a JSON-style `AllOf(Token('"'), ScanUntil(stopAt).As("body"), Token('"'))` parsed against `""`. The body Symbol's SourceRange returns null, so an editor highlighting empty strings has nothing to highlight and a consumer reading the body's offset has nothing to read. The composite-empty-leaf tests pin the inner-empty-leaf-skip behavior; no test pinned the standalone-leaf shape, so this slipped through.
    - Fix lifts the standalone-leaf branch out of the FindFirstLeafWithText path and recovers the position via `MemoryMarshal.TryGetString` directly. The recursive composite walk's skip-on-empty stays unchanged, so the existing composite tests keep passing.
    - Other findings deferred as not-real-bugs: `OneOfRule`, `AnyTokenRule`, `NoneOfRule`'s rune-pinning leaf-Id pattern (`runeValue >= 0 ? new SymbolId(runeValue) : Id`) is documented and intentional. The same pattern in `WithinTokenRule` is filed separately under backlog w1th. `ScanWhile`'s `minimumCount >= 1` enforcement at construction means it can't produce an empty leaf. `Token` / `Literal` / `LiteralIgnoreAsciiCase` reject empty expected text at construction and always consume at least one char on success. `Token.RuneValue`'s Length-2 mismatched-surrogates returning `-1` is correct, and the lexer doesn't produce non-paired Length-2 tokens in normal use.
