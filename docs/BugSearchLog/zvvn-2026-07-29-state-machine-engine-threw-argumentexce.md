    - Method that found it: instead of re-treading the differentially-verified cores, followed the new `MalformedInput` branch (commit 9820520) out to every engine that should mirror it. `FindFirstUnnormalizableIndex` had three callers, all in `src/`: `UnicodeNormalization` itself and two in `Rule.cs`.     - Found and fixed: `StateMachineParser.NormalizeIfRequested` called `UnicodeNormalization.Normalize` with no rejection scan and no catch, so a normalizing parse of input with an unpaired surrogate or U+FFFE threw a raw `ArgumentException` out of `Parse`, `TryMatch`, and the counter entry points, where the recursive engine returns a `MalformedInput` result at the offending code unit. `Rule.Parse` dispatches to the engine hook before `ParseRecursive`'s scan, so routing through `Rule.Parse` didn't help. Fixed by replacing the helper with `TryNormalizeIfRequested` (scan first, `ArgumentException` backstop at index 0, mirroring `Rule.ParseRecursive`): `Parse` builds the same `MalformedInput` result via `Rule.BuildMalformedInputMessage`, and `TryMatch` / `RunAndReduce` / `RunWithCaptureReducer` collapse it to their failure values the way they already collapse budget aborts.

Full state-machine suite green (115), everyday `./test.sh` green (7783 in the main assembly).
