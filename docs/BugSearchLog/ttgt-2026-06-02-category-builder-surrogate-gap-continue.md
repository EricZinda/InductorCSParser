- 2026-06-02: Category-builder surrogate-gap `continue` skipped closing the open interval run (hardened). Broad performance-optimization sweep otherwise clean
    - Focus per user request: places where a performance optimization can create a bug. Random/strategic start in the optimization-heavy files rather than a single random pick.
    - Hardened (behavior-preserving): `TokenSet.BuildCategories` and `TokenSet.BuildInlineWhitespace` build code-point intervals in a single ascending scan and skip the surrogate block U+D800..U+DFFF with a bare `continue`. That `continue` skipped the branch that CLOSES an open run, so a category (or whitespace run) with members at both 0xD7FF and 0xE000 would have merged into one interval that swallowed the surrogate code units, putting surrogates into a set the design says is surrogate-free. Not triggerable on the Unicode the BCL ships today (0xD7FF is Cn, 0xE000 is Co, so no category straddles the gap), so it is not reproducible with a failing test against current data. Fixed anyway at the user's direction: the skip now closes every open run and jumps `codepoint = 0xDFFF` past the block. Verified byte-identical output for current data (all XID-vs-UCD and Unicode fixtures still pass). No regression test was added, because a test asserting "no category set contains a surrogate" passes against the old `continue` too (current Unicode never straddles the gap) so it wouldn't fail-before-fix, and `BuildCategories` reads live `CharUnicodeInfo` data and is private so a synthetic straddling category can't be injected without extracting the run-coalescing loop into a predicate-driven helper. Left as a source-only hardening. A future hunter who wants a real regression test can extract that helper and feed it a predicate that's a member at both 0xD7FF and 0xE000, asserting two intervals rather than one.
