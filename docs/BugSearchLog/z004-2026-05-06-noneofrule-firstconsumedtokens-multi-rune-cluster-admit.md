    - Found and fixed: `NoneOfRule.ComputeRuleStart` returned `~_set.RunesOnlyPart`, treating "first rune of the read token" as "first rune of an admitted single-rune token." That ignored the second admit path: a multi-rune grapheme cluster whose chars aren't in `_set`'s multi-rune part is also admitted, and a multi-rune cluster can start with ANY base rune (including runes in the rune-only part). `OneOrMore(NoneOf(TokenSet.Single('a'))).Compile(null).Parse("a" + CombiningAcuteText)` failed at offset 0 because the BetweenInclusive shortcut peeked 'a', saw it wasn't in `~{'a'}`, and concluded NoneOf couldn't match. NoneOf would have accepted the cluster directly. Same shape via `FirstOf(NoneOf(...), other)`. Backlog n7mh has the write-up.
    - The fix replaces the body with `return new RuleStartRequirements(TokenSet.Universe, Advance.Always);`. The optimization loss is one extra `lexer.Read` per stopper-encountered position in scanner loops like `OneOrMore(NoneOf("\""))`. Both engines correctly stop applying the skip on Universe (`Rule.CannotMatchLookahead` returns false because `Universe.Contains(R)` is true; `Lowerer.cs` line 530 explicitly gates the SM optimization on `child.FirstConsumedTokens.Equals(TokenSet.Universe)` returning false).
