- 2026-05-05: Required-literal prefilter sweep (rune sets with multi-rune entries)
    - Reviewed: `OneOfRule.ComputeConcatenableText` / `ComputeRequiredLiteral`, `LiteralRule.ComputeRequiredLiteral` / `ComputeConcatenableText`, `LiteralIgnoreAsciiCaseRule.ComputeRequiredLiteral` / `ComputeConcatenableText`, `GraphemeRule.ComputeRequiredLiteral` / `ComputeConcatenableText`, `AllOfRule.ComputeRequiredLiteral` / `ComputeConcatenableText` / `ComputeRequiredLiteralAlternatives`, `BetweenInclusiveRule.ComputeRequiredLiteral` / `ComputeConcatenableText`, `FirstOfRule.ComputeRequiredLiteralAlternatives`, `Rule.TryGetRequiredLiteral` / `TryGetRequiredLiteralAlternatives`, `TokenSet.TryGetBmpChars`, `TokenSet.HasMultiRuneGraphemes`. Also the rebar consumer in `ExperimentalSrc/BenchMarks/Rebar/BenchmarkPlan.cs` to confirm what callers depend on.
    - Categories: contract violations between the static-analysis-derived literal and what the rule actually matches, multi-rune cluster handling in static analysis (mirror of the runtime sweeps), conservative-vs-aggressive prefilter trade-offs, propagation through composite rules.
    - Found: `OneOfRule.ComputeConcatenableText` consulted `_set.TryGetBmpChars` on the rune-only part and ignored any multi-rune entries. For a mixed set like `Single('a') | Runes("\r\n")` it returned `("a", false)` even though the rule also matches the CRLF cluster, whose consumed text contains no "a". Broke the `TryGetRequiredLiteral` "every match contains this literal" contract, so a grep-style prefilter could silently skip matchable input. Backlog n4q7 had the write-up. The other `ComputeRequiredLiteral` overrides (Literal / LiteralIgnoreAsciiCase / Grapheme) all return their `_expected` text which is exactly the matched span, so the contract holds for them. Composites (AllOf, BetweenInclusive) inherit the OneOf bug when wrapping a OneOf with a mixed set.
    - The fix is a one-line guard at the top of `OneOfRulePrefilter.ComputeConcatenableText` (in `ExperimentalSrc/InductorParser.Prefilter/OneOfRule.cs` after the prefilter was extracted from core) that returns null when `_set.HasMultiRuneGraphemes` is true. `ComputeRequiredLiteral` already delegates to `ComputeConcatenableText`, so the fix covers both paths. Conservative (skips the prefilter for mixed sets, which are the small hand-built classes where a per-line first-rune skip already wins anyway) but never violates the contract. Regression test in `ExperimentalSrc/InductorParser.Tests/Prefilter/OneOfRulePrefilterTests.cs`.
