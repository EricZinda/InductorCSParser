- 2026-05-25: AliasRule breaks parse-time vs post-hoc-Flatten symmetry (PreserveAllSymbols+Flatten ≠ default) for a leaf-shaped aliased match
    - Random start: picked 31901, mod 29 top-level `src/InductorParser/` `.cs` files = index 1 → `AliasRule.cs`. Already swept (`2026-05-15-aliasrule-rebadge-drops-preserve-leaf-inner-text`, `2026-05-15-aliasrule-drops-latebound-preserve-target`), so per the item read it, noted the prior coverage, and followed threads out rather than re-treading the same categories. The bug turned out to be back in `AliasRule` via a path those entries didn't cover.
    - Method: after reading the engine end-to-end and finding it clean, ran differential fuzzers for the documented equivalences. ScanWhile/ScanUntil vs OneOf/NoneOf loops (8000 inputs), scanner-skip vs unoptimized (36000), NormalizedPositionMap source-text round-trip under FormC/D/KC (15000), lookahead shortcut on/off via `Rule.DisableLookaheadShortcut` comparing full trees (36000 parses, 4816 grammars), all clean. The break surfaced in the `docs/PotentialBugSources/b000` invariant test: random grammar parsed normally vs under `PreserveAllSymbols` then `Symbol.Flatten()`, comparing serialized trees id-for-id. 330 mismatches, every one through an `Alias`.
    - Bug: `AliasRule.TryParseRule` decided the leaf-rebadge (replace the inner leaf with an alias leaf carrying the alias's Id) on `effectiveFlattenType`, which `PreserveAllSymbols` inflates to Preserve for every rule. So an unnamed (Flatten = transparent) alias over a leaf, and a genuinely-Preserve alias over a Flatten inner leaf, both rebadged the leaf under `PreserveAllSymbols` but were transparent / kept the inner leaf in the default parse. Because a Flatten *leaf* survives post-hoc `Flatten` (it's bubbled up, not lifted), the captured-then-flattened tree carried the alias's custom Id (and a collapsed shape) where the default parse had the inner leaf's rune/inner Id. Demonstrable: `OneOrMore(Alias(OneOf(Runes("ab"))))` on "ab" gave leaves `97,98` (rune ids) in the default parse but `<aliasId>,<aliasId>` after PreserveAllSymbols+Flatten.
    - Fix: gate the leaf-rebadge on the *own* FlattenType of both the alias and the inner (`FlattenType == Preserve && _inner.FlattenType == Preserve`) instead of `effectiveFlattenType`. Genuine rebadge (named alias over a Preserve leaf, e.g. `digitSequence.AliasedAs("year")`) is unchanged. The forced-Preserve capture keeps the inner leaf so it flattens back to the default. Composite-inner branch was already symmetric (it emits the alias's own FlattenType, which lifts back). Two regression tests in `Rules/AliasRuleTests.cs` (`Alias_over_a_leaf_inner_flattens_back_to_the_default_tree`, `Alias_over_a_Flatten_inner_flattens_back_to_the_default_tree`) compare serialized default vs PreserveAllSymbols+Flatten trees. Both fail before the fix and pass after. Full suite green (6887 pass, 2 skip).
    - Pattern doc added: `docs/PotentialBugSources/2026-05-25-tree-shape-decision-reads-effective-flattentype-under-preserveall.md`. A rule whose emitted node identity/shape depends on a rule's *effective* FlattenType (not its declared one) diverges between the default parse and PreserveAllSymbols+Flatten, because PreserveAllSymbols forces every effective type to Preserve. Complements `b000`.
