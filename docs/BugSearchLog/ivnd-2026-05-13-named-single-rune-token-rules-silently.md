    - Found and fixed (tknm):
        1. `Rule.As(string)` at [Rule.cs:414](../../src/InductorParser/Rule.cs#L414) writes `Name` but doesn't reset the auto-pinned `_idAssigned` flag. Combined with `GraphemeRule`'s constructor `SetIdInternal(new SymbolId(runeValue))` for single-rune Tokens, two `Token('a').As("first")` and `Token('a').As("second")` rules both retain `Id = 0x61`. `Compile`'s `AssignNamedIds` skips them because `_idAssigned` is already true.
        2. The Compile-time duplicate-id check `CollectPinnedIds` only flags rules whose `_idUserPinned` is true (the `.As(SymbolId)` path), so it misses this collision. `CheckNameUniqueness` only flags duplicate names. Both gates pass, and `Tree.Find(firstA)` / `Tree.Find(secondA)` then return the same leaf regardless of which rule actually matched.
       Fix shape: in `As(string)`, after `Name = name`, clear `_idAssigned` when `!_idUserPinned`. Compile's `AssignNamedIds` then gives the rule a fresh name-hashed custom-range id. The companion site in [GraphemeRule.cs:91](../../src/InductorParser/GraphemeRule.cs#L91) (`CollectNormalizationOffenders`'s post-normalization rune re-pin) is extended to also skip when `Name != null`, so the custom-range id from `AssignNamedIds` doesn't get clobbered by a re-pin when normalization changes the expected rune (e.g., U+2126 OHM SIGN → U+03A9 GREEK CAPITAL LETTER OMEGA under FormC). Anonymous Token behavior is unchanged: `Token('a')` (no `.As`) still auto-pins to `0x61` so tree walkers can dispatch on `leaf.Id == 'a'`.
    - Regression tests: `Two_named_single_rune_Tokens_of_the_same_rune_get_distinct_ids` and `Named_Token_leaves_carry_the_rule_id_not_the_rune_id` in [src/InductorParser.Tests/Core/IdAssignmentTests.cs](../../src/InductorParser.Tests/Core/IdAssignmentTests.cs). Both verify the distinct-id post-fix invariant from two angles: rule-level `firstA.Id != secondA.Id`, and tree-level `result.Find(firstA) != result.Find(secondA)`.
    - Added pattern doc [docs/PotentialBugSources/auto-pinned-id-survives-identification.md](../PotentialBugSources/auto-pinned-id-survives-identification.md) describing the broader category: any constructor-time auto-pin that survives a later identification call (`.As(string)`) silently denies that call its purpose. The `.As(SymbolId)` overload already guards against this via `IsUserSymbolIdPinned`; the `.As(string)` overload didn't. Watch for any future constructor that sets `_idAssigned` via `SetIdInternal` (currently only `GraphemeRule`). <!-- style-lint-ok -->
