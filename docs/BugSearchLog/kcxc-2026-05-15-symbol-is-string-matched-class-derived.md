    - Found and fixed: `Symbol.Is(string)` matches a Symbol only against names a grammar author gave a rule via `.As(...)`. It compared against the symbol's display-label accessor, which falls back to the class-derived trace label ("And", "OneOrMore", "BetweenInclusive[1..3]") for an unnamed composite and to the rune's text for an unnamed character rule, so `Is("And")` matched every anonymous `And` node and `Is("a")` matched every anonymous `Token('a')` leaf. Fix: resolve the name through `grammarRoot.IdOf(ruleName)`, the index of `.As(...)` names, and compare the resolved id. An unnamed rule has no entry there, so `Is` returns false for trace labels and rune-text defaults, and `Is(string)` lines up with `Rule.IdOf`. Contained to `Symbol.cs`.
    - Regression coverage: `Symbol_Is_with_string_does_not_match_class_derived_trace_name` in `Core/SymbolDisplayNameAndIdOfTests.cs`. Full suite green: 5718 pass / 2 pre-existing skips, all E2E samples pass.
    - Also corrected (doc-only, no failing test): the display-label accessor's doc-comment claimed it returns null for an anonymous composite, but the code and the `Symbol_DisplayName_returns_class_derived_name_on_unnamed_composite` test return the trace label "And". The accessor was also renamed `Symbol.Name` → `Symbol.DisplayName` so the property name itself signals it's a display label, not a dispatch key, and won't tempt the next caller into the same `Is`-via-`Name` mistake. All callers, tests, and docs were updated, and `Core/SymbolNameAndIdOfTests.cs` became `Core/SymbolDisplayNameAndIdOfTests.cs`.
