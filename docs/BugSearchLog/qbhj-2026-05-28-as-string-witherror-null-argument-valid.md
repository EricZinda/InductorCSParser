    - Categories checked: public fluent modifiers that mutate rule state without an explicit null check, set-once checks whose null-input behavior bypasses the check, and silent FlattenType auto-flips reachable from non-validating entry points.
    - Found and fixed: `Rule.As(string)` and `Rule.WithError(string)` accepted `null` as the first argument and silently mutated rule state. `Token('a').As(null!)` flipped Token's default Delete to Preserve via `ApplyIdentificationFlattenPolicy` without setting Name, and the `Name != null` set-once check wouldn't fire on a subsequent call (Name was still null), so a later `.As("real")` quietly succeeded after the policy had already been changed. `OneOrMore(...).WithError(null!, forced: true)` wrote `_errorForced = true` without setting `_errorMessage`, and the `_errorMessage != null` set-once check then let a later `.WithError("real")` (with the default `forced: false`) overwrite the forced flag the first call asked for. Fix: throw `ArgumentNullException` at the top of both methods, before `ThrowIfSealed` and before any field write, matching the order `Rule.Parse(string, ParseOptions)` adopted in `d52ad58`.
    - Regression tests: added `NamedRuleFlattenTests.As_string_rejects_null_name` and `WithErrorTests.WithError_rejects_null_message`.
