- 2026-05-15: AliasRule drops a LateBoundRule's Preserve target under PreserveAllSymbols
    - Not a random-walk sweep. Found while doing backlog item 01n2 ("need tests that test latebound binding to latebound, plus combinations with AliasRule"). Writing the alias+LateBoundRule combination tests surfaced the bug; it was confirmed with an exploratory test that parsed the same grammar twice, once normally and once with `PreserveAllSymbols`, and printed whether the target node appeared (`target layer present -- normal: True, PreserveAllSymbols: False`).
    - Categories swept: every composite that consumes a child Symbol structurally (`AliasRule`'s rebadge is the only rule that decomposes a parsed child's `.Children` at runtime; `AndRule` / `OrRule` / `BetweenInclusiveRule` / `NotRule` / `PeekRule` / `WithinTokenRule` only add or discard whole symbols, verified by grepping every runtime `.Children` read). Also checked the `ComputeRuleStart` cycle path feeding the lookahead-shortcut optimization for alias+LateBoundRule recursion (sound: a cycle leaves the rule at the safe pessimistic default, so the shortcut never wrongly skips).
    - The bug: `Alias(lateBound)` where the LateBoundRule's target is `Preserve` kept the target as a layer under the alias in normal parsing (a documented "corner case" in `AliasRule.cs`), but `PreserveAllSymbols` *dropped* that layer. `PreserveAllSymbols` is a debug mode documented to keep every grammar node; it must only ever add nodes, never remove one. Root cause: `ParseChild` passes a Flatten child the parent's list in normal mode (the child writes into it and returns `Discarded`) but passes `null` under `PreserveAllSymbols` (the child returns a real wrapper instead). `AliasRule`'s rebadge fires on a non-`Discarded` return. In normal mode the transparent LateBoundRule pre-wrote the target wrapper and returned `Discarded`, so the rebadge was skipped and the target survived. Under `PreserveAllSymbols` the LateBoundRule returned the target's wrapper as a real value, and the rebadge then mistook that *forwarded* wrapper for the inner rule's own and lifted its children away, deleting the target node.
    - First fix (narrow): exempt a `LateBoundRule` inner from `AliasRule`'s rebadge. Correct but it left the underlying "corner case" in place: `Alias(lateBound)` still behaved differently from `Alias(target)`.
    - Real fix: the corner case existed because a LateBoundRule's transparency was implemented only at the Symbol-id level, not at the FlattenType level. It was hardcoded `FlattenType.Flatten` (fixed at construction, before `.Bind(...)` reveals the target), and `AliasRule`'s rebadge keys off the direct inner's FlattenType. Made `Rule.FlattenType` virtual and `LateBoundRule.FlattenType` an override that reports the bound target's FlattenType, resolved through any chain of LateBoundRules to the first concrete rule. Resolution happens once in `ValidateCompiled` (single-threaded Compile), so parse-time reads are a plain field read. With that, a LateBoundRule composes into And / Or / Alias exactly as the target rule would: `Alias(lateBound)` now produces the identical tree to `Alias(target)`, in both normal and `PreserveAllSymbols` mode. The narrow rebadge exemption and the manual `outputSymbols.Add` hack in `LateBoundRule.TryParseRule` were both deleted, since the LateBoundRule now arrives at every parent looking exactly like its target.
    - Cycle handling: a `.Bind(...)` chain that loops through LateBoundRules with no concrete rule (`A.Bind(A)`, or `A.Bind(B); B.Bind(A)`) has no FlattenType to resolve. `ResolveTargetFlattenType` walks the chain with a visited-set and throws a clear `InvalidOperationException` at Compile, rather than letting a later FlattenType read recurse into an uncatchable `StackOverflowException`. This replaces the old behavior where such grammars compiled and failed at parse with `DepthLimitExceeded` (which misleadingly read as a deep-input problem rather than a structurally broken grammar). A cycle that runs through an `AliasRule` (which has a concrete FlattenType) still resolves fine and still aborts at parse with `DepthLimitExceeded`, because the structural recursion is real but the FlattenType is not part of the loop.
    - Regression tests in `src/InductorParser.Tests/Rules/`: `AliasRuleTests.Alias_of_a_LateBound_rebadges_the_target_like_aliasing_it_directly` and `Alias_of_a_LateBound_rebadges_consistently_in_normal_and_PreserveAllSymbols_mode` lock in that the alias rebadges the target away identically in both modes. `LateBoundRuleTests.LateBoundRule_reports_its_bound_targets_FlattenType`, `LateBoundRule_FlattenType_resolves_through_a_chain_to_the_concrete_rule`, and `LateBoundRule_FlattenType_read_before_Compile_throws` cover the FlattenType forwarding directly. `Self_bound_LateBoundRule_is_rejected_at_compile` and `Two_LateBoundRules_in_a_base_caseless_cycle_are_rejected_at_compile` cover the cycle rejection.
    - Full suite: 5707 pass, 2 skipped (pre-existing lone-surrogate normalization tests). The 3 `Toml.dll` E2E failures are pre-existing, confirmed by stashing the change and seeing them fail on the clean baseline.
