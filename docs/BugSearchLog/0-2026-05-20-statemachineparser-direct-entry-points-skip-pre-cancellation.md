- 2026-05-20: StateMachineParser's direct entry points skip the pre-cancellation pre-flight that Rule.Parse has, so a pre-canceled signal silently drops on tiny parses
    - Directed start (not random): caller asked for a security-related bug. The 2026-05-19 hunt that fixed the pre-cancellation gap on the recursive engine (`docs/BugSearchLog/0-2026-05-19-pre-canceled-signal-ignored-on-tiny-parses.md`) explicitly left the state-machine engine's own entry points unfixed ("the experimental engine's own API surface and a separate consideration"). The same hunt's WithinToken sub-lexer audit took priority that day, and the SM entry points were tagged as a follow-up. Re-swept the SM dispatch surface: `ExperimentalSrc/InductorParser/StateMachine/StateMachineParser.cs` (Parse, TryMatch, RunAndReduce, RunWithCaptureReducer, plus the four public counter / matcher entry points that route through them), `ExperimentalSrc/InductorParser/StateMachine/Stepper.cs` (the periodic budget checks at `EnterRuleAtDepthBudgetChecks` / `TickPeriodicBudget`), `ExperimentalSrc/InductorParser/StateMachine/Machine.cs`, and the `ExperimentalSrc/InductorParser.Tests/StateMachineBudgetCompareTests.cs` fixture to map the existing budget coverage gap.
    - Categories checked: pre-flight pre-cancellation on the SM's own direct entry points (the four `Parse(rule, input, options)` / `TryMatch(rule, input, options)` / `CountMatches` / `EnumerateMatchSpans` / `CountMatchesAndCaptures` / `HasAnyMatch` shapes), whether routing through `Rule.Parse` already covers the gap (yes, but only when the caller invokes `rule.Parse(input, options)` with `UseAlternativeEvaluator = true`, not when they invoke `StateMachineParser.Parse(rule, input, options)` directly), the `NormalizeIfRequested` step that runs before `ConfigureBudgets` and the cost on a huge pre-canceled input, and whether the `EngineSelectionFixture` registering `Rule.AlternativeEvaluator = StateMachineParser.Parse` makes the gap moot under the suite (no, the fixture only re-routes `rule.Parse` calls, not tests that name `StateMachineParser.Parse` directly).
    - Found and fixed: a caller who constructs a `ParseCancellation`, calls `Cancel()` before parsing, and invokes `StateMachineParser.Parse(rule, input, options)` directly on a parse small enough to finish below the 1024-invocation periodic-check boundary gets back `ParseOutcome.Success`. The matcher / counter entry points return their "matched" answer too (`TryMatch` returns true, `CountMatches` returns the real count, `HasAnyMatch` returns true, etc.). This contradicts `ParseCancellation.cs`'s documented behavior ("On the next check after `Cancel()` fires, the parse aborts with `ParseOutcome.Canceled`"). The same shape on the recursive engine was fixed at `Rule.Parse` on 2026-05-19, but the SM's own surface still calls `ConfigureBudgets` (which only stashes the cancellation reference) and then enters `Stepper.Run`, which polls the flag only every 1024 invocations through `CheckPeriodicBudgets`. Pre-flight check added at every public SM entry point. `Parse` returns `ParseResult.Aborted(ParseOutcome.Canceled, ..., Rule.BuildBudgetMessage(...))` matching the recursive engine's wording. `TryMatch` returns `false`. `RunAndReduce<T>` returns the caller-supplied `failureValue`. `RunWithCaptureReducer` returns `0`. The check is placed before `NormalizeIfRequested` so a huge pre-canceled input doesn't pay the normalize cost either. The four indirect entry points (`CountMatches`, `EnumerateMatchSpans`, `HasAnyMatch`, `CountMatchesAndCaptures`) inherit the fix because they route through `RunAndReduce` / `RunWithCaptureReducer`.
    - Fix at `ExperimentalSrc/InductorParser/StateMachine/StateMachineParser.cs`: pre-flight in [Parse(Rule, string, ParseOptions)](../../ExperimentalSrc/InductorParser/StateMachine/StateMachineParser.cs), [TryMatch(Rule, string, ParseOptions)](../../ExperimentalSrc/InductorParser/StateMachine/StateMachineParser.cs), [RunAndReduce of T](../../ExperimentalSrc/InductorParser/StateMachine/StateMachineParser.cs), and [RunWithCaptureReducer](../../ExperimentalSrc/InductorParser/StateMachine/StateMachineParser.cs). Four regression tests in [StateMachineBudgetCompareTests.cs](../../ExperimentalSrc/InductorParser.Tests/StateMachineBudgetCompareTests.cs). `Pre_canceled_signal_aborts_StateMachineParser_Parse_on_tiny_parses` verifies that pre-canceled `Token('a').Parse("a")` returns `Canceled` with the templated message. `Pre_canceled_signal_aborts_StateMachineParser_TryMatch_on_tiny_parses` verifies it returns `false`. `Pre_canceled_signal_aborts_StateMachineParser_count_entries_on_tiny_parses` covers all four reducer-style entries. `Uncanceled_ParseCancellation_does_not_abort_normal_state_machine_parse` verifies that a live but never-canceled signal can't abort. Pre-fix all three "pre_canceled" tests fail (Parse returns Success, TryMatch returns true, CountMatches returns 1). Post-fix they pass.
