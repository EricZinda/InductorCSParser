    - Found and fixed: `Rule.As(string name)` had no null check on `name`. The set-once gate (`if (Name != null) throw`) only fires when a name has already been written, so a first-call `.As(null!)` slipped past, ran `ApplyIdentificationFlattenPolicy` (which auto-flips a class-default FlattenType to Preserve), then wrote `Name = null`. The caller saw `.As` succeed but ended up with an unnamed Preserve rule and a cleared auto-id, and a follow-up `.As("real")` couldn't tell the first call had happened. `AliasedAs(string)` shares the same path via `new AliasRule(this).As(name)`. Fix: add `if (name == null) throw new ArgumentNullException(nameof(name));` at the top of `As(string)`, before any state mutation. Matches the existing `WithError` shape.
