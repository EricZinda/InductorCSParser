- 2026-05-19: WithinToken sub-lexer ignores caller's MaxDepth / RuleCountLimit / Timeout / Cancellation
    - Directed start (not random): caller asked for a security-related bug, so swept the budget/limit code rather than picking a random file.     - Categories checked: pre-flight budget shape (the 2026-05-19 fix for pre-canceled signal only covers Rule.Parse's outer entry), per-iteration budget ticks inside scanner fast paths, missing budget config on freshly-allocated sub-lexers, format-template injection through user input, normalize-before-budget-config timing window, recursive grammar reaching the host stack-limit before MaxDepth fires, integer overflow in counters, behavior on null input / null options, format-template placeholder ordering (`{character}` substitution can't re-introduce `{charIndex}` because position placeholders run first).
    - Found and fixed: `WithinTokenRule` builds a fresh `Lexer` to run its inner rule over the runes inside one outer grapheme cluster, but never copies the caller's `ParseOptions` onto it. The sub-lexer's `_ruleCountLimit / _maxDepth / _timeout / _cancellation` stay at their zero / null defaults, which the periodic check treats as "disabled". A caller who sets `MaxDepth = 100` to protect against stack overflow gets that cap on the outer lexer only. A recursive inner rule (anything that recurses without consuming, or that consumes one rune per recursion through a grapheme cluster crafted with many combining marks) sees no depth bound and recurses until the host stack overflows. Stack overflow is unrecoverable in .NET, so the parser DoS becomes a process crash. Same shape covers `RuleCountLimit / Timeout / Cancellation`: a `Cancel()` fired while the inner is running is not observed until control returns to the outer.
    - Fix design: rather than copying the limits and letting the sub-lexer keep its own counters (which would still leak a fresh `MaxDepth` worth of recursion on top of the outer's depth), `Lexer.InheritBudgetsFrom(Lexer)` now sets a `_budgetParent` pointer. `EnterRule / ExitRule / EnterRuleAtDepth / TickPeriodicBudget` on the sub-lexer all delegate to the parent. The sub-lexer's own `_ruleDepth / _ruleInvocations` stay unused, and MaxDepth and RuleCountLimit cover the COMBINED outer-plus-inner depth and total invocations. The `Stopwatch` and `ParseCancellation` reach the inner through the same delegation. Sub-lexers can nest (WithinToken inside WithinToken) and the delegation chains through. `ResetForReuse` clears `_budgetParent` so a pooled lexer can't carry a stale parent reference into a new top-level parse.
    - Tests added to BudgetTests.cs:
        - `WithinToken_inner_rule_honors_outer_MaxDepth`: `WithinToken(Or(And(AnyToken(), self), Eof()))` against `"a" + 50 * U+0301` (one UAX #29 cluster, 51 sub-tokens) with `MaxDepth = 10`. Pre-fix it returned `Success`. Post-fix it returns `DepthLimitExceeded`.
        - `WithinToken_inner_depth_combines_with_outer_depth`: discriminates between the delegation design and a counters-stay-separate fix. Outer is 14 nested `And` rules above `WithinToken(rec)`, so the outer is at depth 15 when WithinToken's body starts. The inner peaks at ~9 frames on its own, well under `MaxDepth = 20`. A counters-separate fix would let the inner succeed, but the delegation fix correctly trips because 15 + 9 > 20.

    - Pattern: docs/PotentialBugSources/0-2026-05-19-fresh-sub-lexer-doesnt-inherit-parse-budgets.md (the broader category, "a code path that constructs a new Lexer for a sub-parse but doesn't delegate budget tracking to the outer, so MaxDepth/RuleCountLimit only see the outer's work").
    - Cleared: ScanWhile / ScanUntil's per-iteration loops do skip the periodic budget check, but that's by design (the rule is one invocation regardless of run length and the comment block documents it). The pre-flight in Rule.Parse covers both engines (recursive and alternative evaluator hook). WithinTokenRule's inner-failure-position handling (the `RecordFailure` calls) already snaps mid-cluster sub-lexer positions back to the outer cluster's start, so the position fix doesn't interact with this one. The PreserveAllSymbols flag is intentionally not propagated into the sub-lexer because inner-rule Symbols are discarded anyway (WithinToken emits one leaf per token to the outer tree). The TraceSink is intentionally not propagated either (inner trace would interleave confusingly with the outer trace).
    - Not a bug, considered: a `WithinToken` whose inner rule is non-recursive is already bounded by the sub-lexer's input size (one grapheme cluster's runes, typically < 100), so the practical exploit surface is recursive inner rules. The delegation fix still applies the same way: every inner EnterRule increments the outer's counters, and the bound is enforced wherever it would have been on a flat parse.
