    - Bug found + fixed: docs/UnicodeGotchas.md said "Rust identifiers ... uses NFKC" and compiled the recipe with `NormalizationForm.FormKC`. Rust normalizes identifiers with NFC, not NFKC (Rust Reference "Identifiers", RFC 2457). Only Python 3 uses NFKC (PEP 3131). The doc even flags that distinction for Python on the line just above, then copies NFKC onto Rust by mistake. Demonstrable: `Identifier(extraStartRunes: Runes("_")).Compile(FormKC).Parse("x" + circled-one)` (U+2460 CIRCLED DIGIT ONE, category No, NFKC form "1") succeeds because input normalization rewrites it to "x1", while real Rust (NFC keeps U+2460, not XID_Continue) rejects it. FormC matches Rust and rejects it. Fix: changed the recipe to `FormC`, corrected the prose with an RFC 2457 citation, and updated the Rust_identifier_recipe test in DocExamples/UnicodeGotchasExamples.cs to compile FormC and assert the circled-digit string is rejected (would fail under the old FormKC).
