If one child converted cleanly and a later child reported a multi-grapheme offender, `Compile` threw but the root stayed unsealed with the earlier child's converted state still applied. Repro: `And(Literal(Kelvin sign U+212A).Preserve(), Token(fi ligature U+FB01).Preserve())`. `Compile(FormKC)` throws because the ligature expands to `fi`, then a retry against the same graph is unsafe because the Kelvin literal may already have been rewritten to ASCII `K`.
    - Fix: `Rule.Compile` now treats the id-assignment / validation / normalization / sealing region as the mutating compile phase. If any exception escapes that phase, every reachable rule that was touched by the compile attempt is marked invalid. Later `Compile` calls against the root or any touched child throw with a rebuild-the-grammar message instead of parsing with partially compiled state. Pure pre-mutation validation failures, such as duplicate explicit ids or duplicate names, remain retryable because no compile state has been written yet.
