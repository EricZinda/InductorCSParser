- 2026-06-02: Identifier(FormKC/FormKD) no longer promotes continuation-only compatibility pieces into XID_Start
    - User request: keep finding Unicode edge-case bugs. Random pick was `401056`. Over the 28 alphabetically sorted top-level source files under `src/InductorParser/`, `401056 mod 28 = 12`, which landed on `NotRule.cs`. That file and its lookahead siblings were already heavily swept, so the hunt followed the Unicode normalization trail out through `PeekRule.cs`, `AndRule.cs`, `OrRule.cs`, `Rule.cs`, `Lexer.cs` / `Lexer.Failures.cs` / `Lexer.Probe.cs`, `SourcePosition.cs`, `SourcePositionConverter.cs`, `NormalizedPositionMap.cs`, `GraphemeClusterIndex.cs`, `SurrogateHelpers.cs`, `TokenSet.cs`, `TokenSet.Xid.cs`, `Rules.cs`, `XidIdentifierTests.cs`, `NormalizationTests.cs`, `WhitespaceRuleTests.cs`, `IntegerRuleTests.cs`, `FloatRuleTests.cs`, and the external-rule API helpers.
    - Cleared along the way: `NotRule` / `PeekRule` zero-width failure anchoring, public source-position clamping, surrogate-boundary category intervals, `FromRanges` callers straddling the surrogate block, existing `DisplayEscape` surrogate rendering fixes, and the generic `TokenSet.WithCompatibilityEquivalents` behavior for ordinary `OneOf` sets. Also dropped a public-lexer `RecordFailure` validation idea as not sufficiently Unicode-specific for this pass.
    - Found and fixed: `Rules.Identifier(NormalizationForm.FormKC/FormKD)` used `TokenSet.WithCompatibilityEquivalents` on the XID_Start set. That helper expands every grapheme in a multi-grapheme compatibility decomposition into the same set. For identifier starts that is too broad: `U+0140 LATIN SMALL LETTER L WITH MIDDLE DOT` is XID_Start and NFKC/NFKD-decomposes to `l + U+00B7`, but `U+00B7 MIDDLE DOT` is XID_Continue only. The old start expansion added the middle dot to the start set, so `Identifier(FormKC).Parse("\u00B7foo")` succeeded. Fix: add a `WithCompatibilityHeadRuneEquivalents` helper for positional start sets and keep all-piece expansion for continuation/body sets.
    - Regression: `XidIdentifierTests.Compatibility_identifier_does_not_promote_continuation_piece_to_start` rejects leading `U+00B7` under both FormKC and FormKD, while still accepting `U+0140foo` and producing normalized tree text `l\u00B7foo`.
