- Summing per-child measurements that aren't context-free across a child boundary
    - A tree-walk that measures the whole by summing a measurement of each leaf (or each child) is only correct when the measurement is context-free: the value for `A ++ B` has to equal `value(A) + value(B)`. UTF-8 byte length is context-free for well-formed text, so `Symbol.GetUtf8ByteCount` summing `Encoding.UTF8.GetByteCount` per leaf looked safe, and was, until two leaves met at a surrogate boundary.
    - The boundary case: one leaf's text ends with a high surrogate and the next leaf's text begins with the matching low surrogate. Each leaf measured alone reads as two unpaired surrogates (U+FFFD, three bytes each). The concatenation `ToString()` produces is instead one four-byte supplementary code point, so the per-leaf sum over-counts by two bytes per such boundary. The same shape would bite any per-leaf char / rune / grapheme count, or any "render each leaf, measure, sum" pass, whenever a UTF-16 surrogate pair, a UAX #29 grapheme cluster, or a normalization unit can straddle the leaf boundary.
    - This is reachable from a real parse, not just hand-built trees: lone surrogates are a documented Compile(null) input (WTF-8 / JSON unpaired-surrogate round-tripping, see `Core/UnexpectedUnicodeTests.cs`). A grammar that Preserve-captures a lone high surrogate and a lone low surrogate with a Delete-flattened char dropped between them yields exactly the two adjacent leaves whose rendered text fuses. Valid surrogate pairs never split this way, because the lexer keeps a pair inside one grapheme-cluster token, so only genuinely lone surrogates produce the shape.
    - When reviewing a "sum a measurement over the leaves / children" method, ask: is the measurement context-free across the boundary, or can the last unit of one child combine with the first unit of the next? If it can combine, three ways out, best first: (1) if the quantity you want corresponds to a contiguous run of the input, measure that run directly in one call instead of reconstructing it from the leaves, which is what the fix below did. (2) Carry boundary state through the walk (e.g. a pending trailing high surrogate) so a unit split across a boundary is still counted once. (3) Materialize the full text and measure it once, always correct but it defeats the no-allocation point of the streaming walk.
    - Surfaced 2026-05-18 in `Symbol.GetUtf8ByteCount`. The fix removed the method outright (its only caller, a benchmark, wanted a contiguous-region byte count, not the rendered-text one). That caller now measures one contiguous input run in a single `Encoding.UTF8.GetByteCount` call, so no per-leaf boundary exists for a pair to split across.
