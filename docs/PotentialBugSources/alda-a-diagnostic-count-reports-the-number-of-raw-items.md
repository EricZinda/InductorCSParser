- A diagnostic count reports the number of raw items when the message's noun is a coarser grouping of those items
  - Shape: a collector accumulates one record per fine-grained problem, then a summary line counts `records.Count` and labels it with a coarser noun. The labels disagree when one unit of the coarser noun contributes many records. Found 2026-06-03 in `Rule.BuildNormalizationErrorMessage`: the normalization-offender list holds one `(rule, original, normalized)` tuple per offending TokenSet entry, but a single `OneOf` / `NoneOf` / `ScanWhile` / `ScanUntil` rule emits one tuple per convertible set member. The header said "`offenders.Count` rules have expected text that isn't in <form>", so `OneOf(TokenSet.Letters).Compile(FormKC)` (one rule, ~501 convertible members) read "501 rules have...". Fix: count distinct rules (`ReferenceComparer<Rule>`) for the header, and keep one detail line per entry below.
  - Why it slips through: the common case is one record per coarser unit (`Token('é')`, `Literal("café")` each contribute exactly one offender), so `records.Count == distinctGroups.Count` and the wrong noun is invisible. It only diverges when a single group fans out into many records, which needs a built-in or hand-built set with many form-unstable members. Tests that assert the message merely *contains* a substring (the existing offender tests check for "fi", "Literal", etc.) never look at the count, so the divergence rides along unnoticed. The buggy number even leaked into a doc-example comment ("1549 rules have...").
  - Where else to check: any place that does `collection.Count + " <noun>s"` where the collection's element is finer-grained than `<noun>`. In this codebase, audit summary/header lines that count: offenders vs rules, leaves vs tokens, failures vs positions, conversions vs entries. The smell is `list.Count` feeding a singular/plural pick whose noun isn't "element of `list`". When the noun is a grouping, count `list.Select(x => x.group).Distinct()` (by reference for rule/object identity) instead.
  - Fix direction: source fix in the message builder, never a caller change. Pick the count that matches the sentence's subject. If the detail list is per-entry but the header speaks of rules, count distinct rules. If you'd rather the header speak of entries, change the noun to "entries" and reword the body sentence. Counting distinct groups is backward-compatible for the one-record-per-group common case.
