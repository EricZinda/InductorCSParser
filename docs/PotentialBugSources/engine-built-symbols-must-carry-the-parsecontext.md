- An alternative engine that builds Symbols must populate the same fields the primary engine does
    - `Symbol` carries two engine-populated fields beyond its id, children, and text: the per-parse `ParseContext` (`_context`) and, for composites, the consumed parseInput span (`_leafChars`). `Symbol.DisplayName`, `Symbol.Is(string)`, `Symbol.SourceRange`, and `Symbol.SourceText` all silently degrade when those fields are missing. The failure modes are a null display name, a false dispatch, a parseInput-coordinate leak under normalization, and an empty range or text. None of those accessors throw on a missing field, so the gap surfaces as wrong data, not a crash, and only on inputs that exercise the field (a normalized parse, a `.As(name)` lookup).
    - The recursive engine populates both at every Symbol-construction site. 32f7ad1 added a `lexer.Context` argument at 15 rule sites, and every composite records `lexer.Input.AsMemory(matchStart, matchLength)`. The state-machine engine's `TreeBuilder` is a second, independent Symbol-construction path, and it was not kept in sync. It omitted the `ParseContext` entirely (fixed 2026-05-18) and still records no composite span (backlog 0001).
    - When reviewing any code that calls `new Symbol(...)` outside the rule files in `src/InductorParser/`, such as a new evaluator, a tree-rewriting pass, or a fixture that wants the real accessors to work, ask whether the Symbol gets the same `ParseContext` and the same consumed span the recursive engine would have given it. If not, `DisplayName` / `Is(string)` / `SourceRange` / `SourceText` are quietly wrong on that subtree. A search for `new Symbol(` across `src/` and `ExperimentalSrc/` enumerates the construction sites, and each one that isn't `Symbol.Discarded` should pass a context.
    - This is a specific instance of the broader recursive-vs-state-machine divergence pattern (`recursive-vs.-state-machine-engine-divergence`). Any per-parse data the recursive engine carries has to be carried by the SM engine too, or the two engines produce trees that compare equal on `ToString()` but differ on every ParseContext-derived accessor.
