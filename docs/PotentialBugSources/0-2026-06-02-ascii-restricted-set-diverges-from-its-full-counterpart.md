- An "ASCII" (or otherwise restricted) variant of a set drifts from the full set restricted to that same range

  - Shape: a library exposes both a full set `X` and a narrower `Ascii.X` (or `Fast.X`, `Bmp.X`, etc.) that's meant to be "`X` but only inside this range." The invariant a user assumes is `Ascii.X == X ∩ AsciiRange`. When the two are built by separate hand-written expressions instead of one deriving from the other, they drift: the narrow one quietly omits (or adds) a member, and the relationship breaks silently. A grammar that swaps one for the other changes which characters match with no error.
  - Concrete instance (2026-06-02): `TokenSet.Ascii.AnyWhitespace` was hand-built as `{SPACE, TAB, CR, LF, CRLF}` and omitted VT (U+000B) and FF (U+000C), even though the full `TokenSet.AnyWhitespace` includes them (they're line terminators in `TokenSet.LineTerminators` / `IsLineTerminator`). Its sibling `Ascii.InlineWhitespace` *did* equal `InlineWhitespace ∩ ASCII`, so only one of the two ASCII variants held the invariant. The asymmetry between siblings is the tell.
  - Why it hides: each set has its own focused unit test that checks a few members in isolation (`contains space/tab/cr/lf`), and those pass. Nothing cross-checks the narrow set against `full ∩ range`. The narrow set's doc often *claims* the relationship ("ASCII whitespace including line terminators", "the regex `\s` set"), so the doc reads as correct while the membership disagrees.
  - Where else to look: any paired full/restricted constants, like `Ascii.*` vs the full `*` in `TokenSet`, `Bmp`-only fast paths vs full-range walks, a hand-curated "common case" table meant to mirror a computed one. Also any set whose doc cites an external standard (`\s`, a UAX property, a language spec's character class) without a test that actually compares against that standard.
  - Test that catches it: assert the relationship directly over the whole restricted range, e.g. `for c in 0..0x7F: Ascii.X.Contains(c) == X.Contains(c)`, rather than spot-checking a handful of members. The same loop-over-the-range shape catches a future Unicode-version drift too.
