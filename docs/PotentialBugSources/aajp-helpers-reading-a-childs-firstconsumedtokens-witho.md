- Helpers reading a child's `FirstConsumedTokens` without consulting `Polarity`
    - `RuleStartRequirements` publishes a `(set, advance, polarity)` triple. The intuition is that `set` describes the rule's first-consumed runes, but that's only true under `Polarity.MustBeIn`. Under `Polarity.MustNotBeIn` the same field is a FAIL-set: runes the rule will reject on its first read. Any helper that consumes `FirstConsumedTokens` for filtering / candidate-set construction / lookahead-shortcut composition has to also read `child.Polarity` and either bail out or invert the interpretation. Reading just the set treats a fail-set as a consume-set and gets the answer exactly backwards.
    - Four documented sites have hit this trap, all under the same shape (parent reads child's published set without checking polarity):
        1. `NoneOfRule.ComputeRuleStart` itself once published `~_set` under `MustBeIn`, attempting to express "runes this rule consumes" as the complement of the fail-set. That trap is covered in [complement-derived-firstconsumedtokens-on-negation-rules.md](./complement-derived-firstconsumedtokens-on-negation-rules.md). Fix shape: publish `_set` under `MustNotBeIn` and let consumers do the complement implicitly.
        2. `WithAdvance` / `MatchesAnyOf` / `MatchesAllOf` once kept the original fail-set under `MustBeIn` after dropping polarity due to a non-Always Advance. Covered in [polarity-drop-preserves-fail-set-as-consume-set.md](./polarity-drop-preserves-fail-set-as-consume-set.md). Fix shape: drop to `TokenSet.Universe` under `MustBeIn` (the noncommittal "I don't know what this rule consumes first").
        3. `BetweenInclusiveRule.TryCreateScannerSkip` (recursive engine) unions each non-fallback Or-alternative's `FirstConsumedTokens.LookaheadFirstRunes` into the scanner's candidate set without checking polarity. A `MustNotBeIn` alternative (`NoneOf(stopSet)` is the canonical case) contributes its fail-set to `candidates`, so the scanner advances to FAIL positions and silently skips past every MATCH position. Fix shape: bail out (return `null`) when any non-fallback alternative has `Polarity != MustBeIn` and let the slow path handle the loop.
        4. `Lowerer.TryLowerBetweenScanner` (state-machine engine) has the exact same shape as site 3, lowering the same `ZeroOrMore(Or(match, AnyToken.Delete))` grammar through the SM's `ScannerSkipAdvance` opcode. Same fix (return `false` so the SM falls back to per-iteration `PushBacktrack` lowering).
    - The trap is easy to miss because `MustBeIn` is the common case (every positive leaf, every composite without a `NoneOf` child) and the test suite tends to use `OneOf` / `Literal` as the canonical alternative in shortcut-shaped grammars. `NoneOf`-as-Or-alternative is a legitimate but less-exercised shape, and it's the one that surfaces the bug. When the same scanner-skip primitive is implemented in both the recursive engine and the SM engine, both engines need the polarity gate — one fix doesn't cover the other.
    - The polarity-aware sites that GOT this right and serve as templates: `Rule.CannotMatchLookahead` (Or-shortcut, recursive engine) switches on `Polarity == MustBeIn` vs `MustNotBeIn` and flips the membership test. `Lowerer.CanSkipUnreachableAlt` (Or-shortcut, SM engine) checks `child.Polarity == Polarity.MustNotBeIn` and returns `false`, letting the alternative go through the general `PushBacktrack` path without the peek pre-check. `RuleStartRequirements.MatchesAnyOf` / `MatchesAllOf` pass `child.Polarity` into `Combine`, which OR-composes the polarity-aware predicates.
    - When reviewing new code that touches `rule.FirstConsumedTokens`, ask: does this read assume the set is a consume-set? If yes, also check the rule's `Polarity` and either bail out, invert the test, or drop to `Universe` under `MustBeIn` (the only sound option when the wrapping operation can't preserve `MustNotBeIn` semantics). The recursive engine and the state-machine engine both consume the same compiled `Rule.FirstConsumedTokens` / `Rule.Polarity` fields, so a polarity-confused read in one engine usually has a mirror in the other.
