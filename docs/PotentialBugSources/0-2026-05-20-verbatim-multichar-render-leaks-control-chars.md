- Rendering a multi-character value verbatim into a single-line string leaks embedded control characters
    - When a renderer builds a one-line user-facing string (a trace line, an error message, a debugger view) and appends a value that can be more than one character verbatim, any control character inside that value goes straight into the line. A raw carriage return / line feed turns one logical line into several physical lines and corrupts whatever consumes the trace.
    - The trap is that the single-element path usually already escapes controls, so the code looks safe. `TokenSet.ToString` rendered single-rune entries through `RenderCodepoint` (printable ASCII verbatim, everything else `U+XXXX`), but the multi-rune grapheme entries were appended with a bare `sb.Append(grapheme)`. The CRLF cluster that lives in `LineTerminators` and `Ascii.AnyWhitespace` (U+000D U+000A) then leaked a raw CR/LF, while the single-rune line terminators in the same set rendered correctly as `U+000A` etc. The two paths disagreed on the same kind of character.
    - Fix shape: route the multi-character append through a helper that escapes per element to `U+XXXX` when the char's Unicode General_Category is line-breaking or non-printing (Control / Cc, LineSeparator / Zl, ParagraphSeparator / Zp), otherwise verbatim, so printable content (emoji, ZWJ families, regional-indicator flags, accented clusters) still shows through but line-breakers can't split the line. Read the category from the BCL tables (`CharUnicodeInfo.GetUnicodeCategory`) rather than a hand-kept code-point list so it tracks new Unicode versions. A `char.IsControl`-only check is Cc only and misses U+2028 / U+2029. Leave Format (Cf) chars like ZWJ verbatim, since they're the invisible glue inside emoji clusters and don't break the line. See `AppendGraphemeForDisplay` / `IsControlOrLineSeparator` in `TokenSet.cs`.
    - Where else to look: anywhere a multi-char token, literal, grapheme, or matched span is spliced verbatim into a trace or error string. Candidates: rule trace lines that quote `lexer.Input.Substring(token.Offset, token.Length)` for a multi-rune token, `Rule.ExpectedText` / literal renderings, and any `ToString` on a type that can hold a multi-char member. The `{character}` placeholder work (pattern `c000`) is the sibling concern about showing the right unit. This one is about a correctly-chosen unit still carrying a line-breaking control char.
    - Distinct from `c000-char-unit-rendering-in-user-facing-strings`: that pattern is "show a grapheme, not a UTF-16 code unit." This pattern is "even the right multi-char unit needs its control characters escaped before it goes on a one-line string."
