- "Lift the children" of a wrapped Symbol silently drops a leaf's text
    - A `Symbol` has two shapes: a composite (carries child `Symbol`s in `Children`) and a leaf (carries match text in `_leafChars`, with an empty `Children`). Any code that wants to "unwrap" or "rebadge" an inner Symbol — drop the inner wrapper but keep its content — by iterating `inner.Children` and re-adding each child works for a composite and silently drops everything for a leaf. A leaf's content is *not* in `Children`; iterating an empty list adds nothing and the text disappears from the tree shape.
    - Known instances: `AliasRule.TryParseRule`'s rebadge step lifted `innerSymbol.Children` to hide the inner rule's identity; for a Preserve leaf inner (`Token('a').Preserve()`, `Literal("abc").Preserve()`) the alias became an empty composite and `ToString()` rendered `""` while `SourceText` still returned the text (backlog `0001`). The same root cause hit `Symbol.FlattenInto`'s Flatten branch, which only iterated `Children` and dropped a Flatten leaf's text (backlog `b4xv`, pattern doc `parse-time-vs-post-hoc-flatten-symmetry.md`). <!-- style-lint-ok -->
    - The asymmetry is easy to miss because `ToString()` (walks `Children`) and `SourceText` (reads the recorded `_leafChars` span) disagree only for the broken node — the parse still succeeds, the span is still right, and any test that checks `Success` / `SourceText` / `SourceRange` stays green. The failure only shows up in `ToString()` or in walking `Children`.
    - When reviewing any rule or `Symbol` method that extracts content from an inner Symbol, ask: what happens when that inner is a *leaf*? The fix is always to special-case the leaf (`Symbol.IsLeaf` distinguishes it from a zero-child composite): add the leaf itself, or carry its text onto the new Symbol via the leaf constructor — never iterate its `Children`. Exercise the shape with a Preserve leaf inner (`Token / Literal / OneOf` + `.Preserve()`), not just a composite inner, and assert `ToString()` (not only `SourceText`).
