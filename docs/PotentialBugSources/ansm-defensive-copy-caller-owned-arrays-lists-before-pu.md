- Defensive-copy caller-owned arrays/lists before publishing them as read-only state
    - Shape: a public or protected constructor/factory accepts a mutable array/list, validates it, then stores that exact collection behind an `IReadOnlyList<T>` or similar read-only-looking property. The property blocks mutation through the declared type, but the original caller may still hold the collection reference, or may cast the published value back to the mutable runtime type.
    - Concrete examples: `Rule.ValidateChildren` returned the incoming `Rule[]` directly as `Rule.Children`, so a caller could mutate an already-compiled grammar by editing the original array. Returning a copied array still left a second hole because `Rule.Children` could be cast back to `Rule[]`. `Symbol.Children` and `ParseResult.Symbols` had the same public read-only surface over mutable arrays/lists.
    - Fix shape: copy caller-owned non-empty collections and publish the copy through a non-castable read-only view such as `Array.AsReadOnly`. If the collection is freshly owned by the method and no outside reference exists, wrapping with `List<T>.AsReadOnly()` is fine.
    - Review checklist: every `params` array or array/list accepted by a constructor/factory should either be copied and wrapped, consumed only transiently, or explicitly documented as caller-owned live state. Returning it through `IReadOnlyList<T>` is not enough. This is especially important for objects that promise immutability after a sealing/compile step or represent parse output.
