- A per-code-point interval-building loop that `continue`s over a skipped block must CLOSE the open run, not just step over the code points
    - Shape: a build method scans `for (cp = 0; cp <= MAX; cp++)`, accumulating maximal runs of "members" into intervals, and skips a forbidden sub-range with `if (cp in forbiddenBlock) continue;`. The runs are tracked with an open-run cursor (`currentLow`/`currentHigh`, or per-target `currentLows[]`). A `continue` that skips the block also skips the else-branch that closes an open run, so a run that was open just before the block stays open across it. If the code point just after the block is also a member, the two sides MERGE into one interval that swallows the skipped block.
    - Where it was found: `TokenSet.BuildCategories` and `TokenSet.BuildInlineWhitespace`, skipping the surrogate block U+D800..U+DFFF. The design says category and whitespace sets are surrogate-free (surrogates enter a TokenSet only through `TokenSet.Surrogates` / `SurrogateRange`). A category with members at both 0xD7FF and 0xE000 would have produced an interval `[.., ..]` spanning the surrogates, so `ContainsRune(0xD800)` returns true on a set that's documented never to contain one. Hardened 2026-06-02 (close the open run, then jump `cp = blockEnd`).
    - Why it was latent, not a filed bug: no Unicode category the BCL ships straddles the gap (0xD7FF is Cn / OtherNotAssigned, 0xE000 is Co / PrivateUse), and no whitespace sits at that boundary, so the merge never fires on current data and there's no input that makes a test fail. It's a correctness fragility that silently depends on an external Unicode-adjacency invariant the code never asserts, exactly the "silent defensive code relying on an unchecked invariant" shape CLAUDE.md says to replace with explicit handling. Fixed defensively so the result stays surrogate-free for any category and any future Unicode version.
    - How to spot more: grep for `continue` inside any `for (cp ...)` / `for (codepoint ...)` loop that also maintains an open-run cursor (`currentLow`, `currentLows[]`, `runStart`, etc.). For each, ask "when this `continue` fires, is there an open run that should end here?" If the skipped code points are non-members of every run being built (a forbidden block, an unassigned gap, a filtered category), the run must close at the skip, otherwise a member on each side merges across it. The same trap applies to any future `BuildFromPredicate`-style table builder.
    - Adjacent: `TokenSet.NormalizedFor` / `WithCompatibilityEquivalents` / `EnumerateRunes` walk runes one at a time and handle surrogates per-rune (add each as its own `[rune,rune]` interval or skip individually), so they never carry an open run across the gap and aren't affected. Only the run-coalescing scan loops have this shape.
