- Ill-formed UTF-16 in a generated test-case name makes VSTest silently skip the case
    - Shape: an NUnit `[TestCaseSource]` or `[TestCase]` whose string argument contains an unpaired surrogate puts that raw code unit into the generated test name. Discovery lists the case (`dotnet test --list-tests` shows it), but the discovery-to-execution handoff fails to match it, so the case never runs. No failure, no skip line in the summary, and a `--filter` on the method name reports "No test matches". The test looks written and green while asserting nothing.
    - Why it matters here: this library's whole test surface is Unicode edge cases, and unpaired surrogates are one of its standard probe inputs (the lone-surrogate sweeps, the MalformedInput cases, the TokenSet surrogate members). Any new differential or regression test that passes such a string through a TestCaseSource is exposed.
    - What to do: give every case whose arguments can hold ill-formed UTF-16 (or invisible characters like U+FFFE) a plain-ASCII display name via `TestCaseData.SetArgDisplayNames(...)`. That keeps the raw code units out of the name while the test body still gets the real string. Concrete instance: `StateMachineNormalizationCompareTests.MalformedInputCases`.
    - How to catch it: after adding cases, check the executed-test count went up by the number of cases added, not just that the run is green. A green run with an unchanged count is the failure mode.
