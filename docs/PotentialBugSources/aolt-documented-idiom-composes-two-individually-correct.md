- Documented idiom composes two individually-correct operations into a wrong one

  - The pattern: an API documents a derived operation as a composition of primitives ("set difference is `a & ~b`", "absolute path is `Combine(root, relative)`", etc.). Each primitive is correct in isolation and passes its own differential tests, but the COMPOSITION is only correct under an unstated precondition. Outside that precondition the idiom silently produces a wrong-but-plausible result, and the per-operator tests never catch it because no single operator is wrong.
  - Concrete instance fixed 2026-06-04: `TokenSet`'s "a minus b" idiom `a & ~b`. `~b` complements only over the scalar-value (rune) universe, so it never carries cluster members. The following `&` then intersects `a`'s cluster array against an empty one and drops every multi-rune grapheme `a` had. `Ascii.AnyWhitespace & ~Single(' ')` silently loses the CRLF cluster. The unstated precondition was "`a` is rune-only." Fixed by adding a real `operator -` (true difference) and demoting the idiom in the docs.
  - Why isolation testing misses it: a differential test that checks `&` against reference intersection and `~` against reference complement will report 0 mismatches, because each op IS its reference. The bug lives in the human-language claim that the composition equals some third operation (difference) that the library never actually implemented.
  - Where else to look: any place a doc comment or README says "to get X, just do Y `op` Z" where one of the operands is itself a derived/restricted value (a complement that only covers part of the universe, a clamp, a projection, a "rune-only" or "BMP-only" view). Check what happens when the OTHER operand carries the thing the restricted operand can't represent. Candidates worth a pass: any "set difference / subtraction" idioms, "mask off" idioms (`x & mask`), and "restrict then combine" recipes. If the library deliberately throws on the unsafe primitive in one path (here `~mixed` throws), check whether an adjacent recommended idiom reintroduces the exact silent loss the throw was added to prevent.
  - Test shape that catches it: build the minuend/left operand so it carries the kind of member the restricted operand can't represent (a cluster, a supplementary-plane rune, a surrogate), run the documented idiom, and assert the unrelated member survived. Contrast with the true operation if one exists.
