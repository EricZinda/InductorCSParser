- Parse-time vs. post-hoc Flatten symmetry
    - The parser supports two ways to apply a rule's `FlattenType.Flatten`: at parse time (each rule's `TryParseRule` adds the leaf or each lifted child to the parent's `outputSymbols` list) and post-hoc (`Symbol.FlattenInto` walks a tree captured under `PreserveAllSymbols=true` and rebuilds the collapsed shape). Those two paths are supposed to produce the same tree.
    - Asymmetric handling of the leaf-with-FlattenType.Flatten case is where the two diverge: parse-time leaf rules (`GraphemeRule`, `OneOfRule`, etc.) explicitly add the leaf itself to outputSymbols on the Flatten branch, but `Symbol.FlattenInto` only iterated `Children` for the same case. A leaf has empty Children, so post-hoc Flatten dropped the leaf's text. See backlog b4xv.
    - When reviewing either path, ask: does this shape produce the same Symbols list whether the parse runs through the parse-time lift or through PreserveAllSymbols followed by `tree.Flatten()`? The `Rules.Float()` factory's `Token('-').Flatten(FlattenType.Flatten)` is the canonical "Flatten leaf" shape any test should exercise.
    - Second instance (fixed 2026-06-02): an `AliasRule` over a Delete inner. The deeper trap is that `PreserveAllSymbols` forces every inner to act Preserve, so an inner that would return `Symbol.Discarded` in production returns a real Symbol under the flag. Any code that branches on `ReferenceEquals(x, Symbol.Discarded)` to mean "the inner contributed nothing" misclassifies a Delete inner under PreserveAllSymbols. `AliasRule.TryParseRule` lifted the Delete inner's children (because the `else if (!ReferenceEquals(innerSymbol, Discarded))` branch only checked for Discarded), so the post-hoc Flatten kept content the default parse dropped. Fix: the branch's condition also requires `_inner.FlattenType != FlattenType.Delete`, mirroring the term already in the `EmitsLeaf` check. And/Or/BetweenInclusive don't hit this because they keep the inner Symbol as a child (FlattenInto then re-applies its Delete) rather than lifting, whereas only AliasRule lifts/substitutes. The existing symmetry tests covered leaf and Flatten-leaf inners but not a Delete inner, which is the gap that let it through. See `docs/BugSearchLog/2026-06-02-alias-over-delete-inner-breaks-flatten-symmetry.md`.
