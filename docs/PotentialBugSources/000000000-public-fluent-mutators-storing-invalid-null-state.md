- Public fluent mutators storing invalid null state for later invariant failures
    - Shape: a public fluent method mutates a rule object in place and stores a required argument without validating it. The immediate call appears to succeed, but the invalid value is consumed later by parse/compile internals that reasonably assume the rule graph is already valid. If the later consumer has an internal invariant, the caller sees an `InductorParserBugException` or other implementation-shaped failure for what should have been an argument error at the public boundary.
    - Concrete example: `Rule.WithError(null!, forced: true)` stored `_errorMessage = null` and `_errorForced = true`. On parse failure, `Lexer.RecordFailure(..., forced: true)` hit the invariant that forced failures must have a non-null message. The fix is to validate `errorMessage` in `WithError` before touching rule state.
    - Review checklist: for every fluent mutator that stores caller data (`WithError`, `As`, `Bind`, future option setters), validate required arguments before state checks, duplicate-set checks, graph mutation, or cached metadata updates. Tests should cover the bad argument at the mutator call, not only the later parse/compile path where the corrupted state finally becomes visible.
