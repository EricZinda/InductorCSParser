- Composed public factories silently inherit their inner factory's optional clauses
    - When a public `Rules.X()` factory is built by composing another public factory (e.g. `Rules.Float()` is `AllOf(Optional(...), Integer(), '.', Integer())`), the outer factory's grammar inherits every optional clause inside the inner factory. The author of the outer factory often writes its docstring as if the inner factory matched the minimal underlying primitive (digits-only, in Float's case) and not the full primitive-plus-prefix shape the inner factory actually exposes.
    - The failure mode is silent: the docstring describes a narrow grammar, but the implementation accepts a wider one. The doc and the code drift apart and tests written against the doc pass. The bug only shows up when a downstream caller hits an input shape the doc said wouldn't match. `Rules.Float()` had this shape: documented as `-?\d+\.\d+`, actual grammar `-?[+-]?\d+\.[+-]?\d+` because `Integer()` carries its own optional sign. See backlog `fl0a` for the full write-up.
    - When reviewing a factory in `Rules.cs` that composes other public factories, ask: does the outer factory's documented grammar account for every optional clause every inner factory carries? If the docstring describes an inner factory's contribution as "digits" / "letters" / "the body of an X", verify the inner factory matches *only* that, not "that with an optional prefix sign" / "that with an optional trailing X". The fix is usually to inline the underlying primitive (`OneOrMore(OneOf(TokenSet.Digits))` instead of `Integer()`), not to widen the docstring.
