- Hand-curated Unicode property tables that mirror the BCL's General_Category fall out of sync with their source data
    - When a TokenSet is built as `(category-union | adds) & ~exclusions`, the adds and exclusions arrays are typed in by hand from a Unicode UCD file at one point in time. The General_Category half tracks whatever Unicode version the BCL ships, but the hand-typed half doesn't.
    - Easy failure mode: a range gets dropped or fat-fingered during transcription and the regression tests cover the ranges the author thought to test, not the ones missed. `TokenSet.Xid.cs` `XidStartAdds` had this shape: `(0x309B, 0x309C)` (KATAKANA-HIRAGANA VOICED / SEMI-VOICED SOUND MARK, GC=Sk, in `Other_ID_Start` since Unicode 5.1) was missing from both `XidStartAdds` and `XidContinueAdds`. The "Source: Unicode 17.0 ..." comment at the top of each table named the right UCD file, but the data underneath didn't match it. See commit 8d1a4f9 (closes backlog k309).
    - When reviewing a hand-curated Unicode array, ask: did anyone diff this against the upstream UCD file recently, or are we trusting the original transcription? The "Source: ..." comment doesn't prove the array matches what the comment claims. Pick a couple of code points outside the L+Nl base in the cited UCD file and verify the array lists them.
