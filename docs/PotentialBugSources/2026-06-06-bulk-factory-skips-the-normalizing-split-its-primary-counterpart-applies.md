- A bulk / secondary factory skips the range-normalizing split its primary counterpart applies

  - Shape: a type has two ways to build the same thing from the same raw inputs. The primary one (`Range`, the single-item path) runs a small normalizing transform on its input to keep a type invariant. A second "bulk" or "convenience" path (`FromRanges`, a params array, a from-table constructor) validates the input the same way but skips the transform, on the unstated assumption that the bulk caller already hands in clean data. Both validate, so neither rejects the dangerous input. The bulk path then produces a value that violates the invariant the single path guarantees, and the two factories silently disagree on the same arguments.
  - Concrete instance (2026-06-06): `TokenSet.Range(int, int)` splits a code-point range that straddles the surrogate block (0xD800..0xDFFF) into two intervals so the result never holds a surrogate code unit, enforcing "surrogates enter a TokenSet only through Surrogates / SurrogateRange." `TokenSet.FromRanges` validated each tuple's endpoints (both must be valid scalars) but added the interval verbatim with no split, so `FromRanges((0, 0x10FFFF))` admitted the whole surrogate block while the identical `Range(0, 0x10FFFF)` didn't. Endpoint validation passed because the endpoints themselves are valid scalars. The interval between two valid scalars can still cover an excluded sub-range.
  - Why it hides: the invariant-preserving split lives in the single-item factory, so a reviewer reading that factory sees the protection and assumes the type as a whole holds the invariant. The bulk factory's own validation looks thorough (it checks every endpoint), which reads as "fully checked." Tests for the bulk factory tend to feed it already-clean tables (the real callers' data), so the one input that needs the split, an endpoint pair bracketing the excluded range, never appears. A prior sweep can even "clear" the bulk factory by confirming its internal callers stay clean, which says nothing about the public API.
  - Where else to look: any pair of `X(single)` and `X(bulk/params/from-table)` where the single path runs a clamp, split, drop-empties, or surrogate/normalization fix-up. The tell is a normalizing helper called on one path but not the sibling that accepts the same element type. Check whether the bulk path can receive an element whose endpoints pass validation but whose interior crosses an excluded region.
  - Test that catches it: build the same logical set both ways and assert value-equality (`FromRanges((0, MAX)) == Range(0, MAX)`), and assert the invariant directly on the bulk result (no excluded members, empty `EnumerateSurrogates()`). Spot-checking a few in-range members won't surface it. The boundary input, an endpoint pair bracketing the excluded block, is the one that matters.
