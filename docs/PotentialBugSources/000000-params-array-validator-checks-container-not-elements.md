- Params-array validators that check the container but not its elements
    - Public `params` factories need two layers of validation: the array object / length, and each element inside the array. Checking only `children == null || children.Length == 0` lets `Factory(goodRule, null!)` build an object whose invariant is already broken. The failure then appears later as a null-reference crash during compile, parse, traversal, or trace instead of as a construction-time argument error.
    - Worked case: `Rules.And(params Rule[] children)` and `Rules.Or(params Rule[] children)` rejected a null or empty array but didn't reject a null child element. The fix put null-element rejection in the base `Rule` constructor, where every child-bearing rule passes through. `AndRule` / `OrRule` validate that their child arrays are non-empty because leaf rules legitimately have zero children.
    - Review checklist: for every public `params` API over reference types, scan for both checks. Also check forwarding factories where the callee validates a single argument but not an array element, because `params` can hide the difference between "no children" and "one child is null" at the caller.
