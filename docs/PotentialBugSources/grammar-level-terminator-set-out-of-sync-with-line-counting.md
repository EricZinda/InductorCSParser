- Grammar-level terminator set drifts out of sync with line-counting set
    - Parsers usually carry two parallel "what counts as a newline" definitions: one for the grammar layer that has to accept the terminators in input, and one for the position-reporting layer that decides when to bump the line counter. The trap is letting the two sets drift. Concrete InductorParser case: Rules.EndOfLine() accepted UAX #18 Annex C R1 (LF, CRLF, lone CR, VT, FF, NEL U+0085, LS U+2028, PS U+2029) while SourcePositionConverter.ToLineColumn counted only the LSP-strict subset (LF, CRLF, lone CR). A grammar that consumed any of the non-LSP terminators got an ErrorLine pointing at the prior line, off by one.
    - The two sets each had good local docs: Rules.cs EndOfLine pointed at UAX #18 Annex C explicitly, SourcePosition.cs claimed LSP convention. Neither doc mentioned the other surface, and neither test fixture covered the cross product. EndOfLineRuleTests confirmed EndOfLine matches NEL / LS / PS / VT / FF. ErrorPositionTests confirmed Line bumps for LF / CRLF / lone CR. Nothing asserted "EndOfLine matched it → Line bumped for it."
    - When auditing a similar parser, the question is: enumerate every "what is a newline" decision the code makes (grammar matching, line counting, column counting, trace rendering, sub-lexer mode, normalization passes that might touch line breaks) and check the sets agree. A cross-product test that consumes each terminator via the grammar layer and then asserts the position-reporting layer bumped is the cheap way to lock the agreement in for the next change. The fix is whichever direction makes the grammar's stated terminators show up in the reported position math.
    - Same shape can hit other "what counts as X" pairs in any parser: what counts as whitespace for skip vs. for tokenization, what counts as a word boundary for `\b` vs. for the identifier rule, what counts as a digit for hex literals vs. for radix detection. The fix is always "pick one definition and route both surfaces through it," or "publish both definitions explicitly and document how the two surfaces relate."
