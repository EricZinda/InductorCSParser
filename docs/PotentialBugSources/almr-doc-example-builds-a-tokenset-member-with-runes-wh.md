- Doc example builds a TokenSet member with Runes() when the member is a multi-rune grapheme cluster
  - Shape: prose or a code block wants "this emoji / flag / decomposed accent as one set member" and writes `TokenSet.Runes("<cluster>")`. `Runes(string)` walks the input rune by rune and throws ArgumentException the moment two consecutive runes form one grapheme cluster (regional-indicator flags, ZWJ emoji, skin-toned faces, NFD base+combining-mark, CRLF). The factory that accepts a multi-rune cluster as one member is `Graphemes(params string[])`. `Runes` is the single-rune shortcut only.
  - Why it slips through: the example reads naturally and the throw is at construction time, not parse time, so it only fires when someone actually runs that block. If no DocExamples test mirrors the block, nothing catches it. The two hits found on 2026-06-03 (primer1.md, InductorParserReference.md) were both uncovered.
  - Where else to check: any doc/comment that passes an emoji, a flag, or a combining sequence to `Runes(...)` or to `OneOf(string)` / `NoneOf(string)` (which forward to `Runes`). Single-rune emoji that fit one scalar (😀 U+1F600) are fine through `Runes`. The trap is specifically multi-rune clusters. Grep for emoji/flag literals inside `Runes(` and `OneOf("`/`NoneOf("` across docs and code comments.
  - Fix direction: name `Graphemes(...)` for cluster members. The `Runes` rejection is intentional and has a pointed error message (see BugSearchLog/2026-05-30-tokenset-runes-surrogate-extender-diagnostic.md), so this is a caller/doc fix, never a source change.
