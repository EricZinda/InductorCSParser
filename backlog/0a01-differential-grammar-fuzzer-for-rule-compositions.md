# Differential grammar fuzzer for rule compositions

- Where this came up: the 2026-07-10 discussion of where bugs could still hide after 151 recorded hunts.
- The gap: the entries in docs/BugSearchLog share one shape. Read a file (plus siblings that share its pattern), check a known category, verify with a single parse. That mined out the per-file space, but nothing has ever tested random *combinations* of rules: a ScanUntil whose stopper set shares members with an outer Or, a Not around a transparent alias, an Optional inside Exactly. The composition space is combinatorial, so hand-reading can't cover it.
- Why a fuzzer works here: the library has oracles that need no expected-output files, so every generated case checks itself.
    - A grammar compiled with FormC and the same grammar compiled with null normalization must agree on outcome, error index, error message, and tree, for input that's already NFC.
    - A PreserveAllSymbols debug parse, post-hoc flattened with Symbol.Flatten(), must reproduce the production tree exactly.
    - Wrapping any subrule in an unnamed Alias(...), or binding it as the target of a LateBoundRule, must change nothing: same tree (compared by name, since ids shift), same outcome, same error position and message. Those are the two transparent stand-in rules.
    - On success, every node's SourceText must equal the input text at its SourceRange, and every range must be in bounds.
    - Parsing the same input twice on the same compiled grammar must give identical results.
- The plan: a generator that produces random small grammar blueprints over the public factories (And, Or, Optional, ZeroOrMore, OneOrMore, Exactly, Token, Literal, LiteralIgnoreAsciiCase, OneOf, NoneOf, ScanWhile, ScanUntil with and without escapes, AnyToken, Eof, EndOfLine, Not, Peek, Alias, plus the .As / .Flatten / .Delete / .WithError modifiers), respecting the API's legality rules (unique names, no .As after an explicit non-Preserve flatten). Inputs are biased toward the grammar's own terminals so matches actually happen, mixed with newlines, CRLF, quotes, and NFC-stable non-ASCII. A failure prints the seed, the grammar expression, and the input, which is the failing repro the find-a-bug flow requires.
- Growing it: built-in TokenSets as set sources, explicit .As(SymbolId) ids, Identifier extras beyond the underscore profile, FormKC / FormKD grammar text, non-default ParseOptions, and the error-report rewrite oracles tracked in backlog 0a02. Level 2 already added LateBound recursion, WithinToken inners, rule-valued stoppers, corpus-driven Unicode grammar text, and the FormC-vs-FormD oracle, and a follow-up pass added every remaining factory (Identifier sits behind the rune-level oracle gate). The harness header lists the current gaps.
- Done when: the harness lives in the test project (an [Explicit] fixture or a standalone tool is fine), a fixed seed range runs green on demand, and every divergence it finds is either filed as a bug or added to the known-non-bug list in the find-a-bug backlog item.
