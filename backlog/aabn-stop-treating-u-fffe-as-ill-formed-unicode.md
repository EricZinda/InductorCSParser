# Stop treating U+FFFE as ill-formed Unicode during normalization

The parser currently rejects U+FFFE whenever normalization is enabled and reports it as malformed input. This deliberately matches a `string.Normalize` quirk on current .NET, but it isn't Unicode-conformant: U+FFFE is a noncharacter yet still a valid Unicode scalar value, Corrigendum #9 explicitly says noncharacters don't make Unicode text ill-formed, and all four normalization forms leave U+FFFE unchanged. The inconsistency is especially visible because every other noncharacter, including U+FFFF, U+FDD0..U+FDEF, and the supplementary-plane `nFFFE`/`nFFFF` values, is accepted.

Remove U+FFFE from `UnicodeNormalization.FindFirstUnnormalizableIndex` and from the malformed-input rules in `Rule`, `ParseOutcome`, `ParseOptions`, tests, and docs. Preserve cross-runtime behavior even though the runtime-backed implementation calls a .NET API that rejects U+FFFE: either handle strings containing U+FFFE through a standards-conformant path before calling `string.Normalize`, or route that case through the bundled normalizer. Don't confuse U+FFFE found in an already-decoded C# string with the byte-order diagnostic that applies when decoding a serialized UTF-16 stream.

Add coverage proving that U+FFFE normalizes to itself under FormC, FormD, FormKC, and FormKD, that `IsNormalized` returns true, that a default-normalizing grammar can compile literals containing it and parse input containing it, that position mapping stays correct around it, that all 66 noncharacters have a consistent pass-through policy, and that lone surrogates stay rejected as genuinely ill-formed UTF-16. Remove the U+FFFE exception from the Part1 corollary in `NormalizationConformanceTests` so the official UAX #15 identity requirement is exercised without a local standards exception.

Also clean up the test terminology that currently hides the distinction: `UnicodeNormalizationTests.Ill_formed_text_throws_from_both_implementations` puts U+FFFE in an `illFormed` array alongside lone and reversed surrogates. Split the valid-noncharacter compatibility case from the genuinely ill-formed UTF-16 cases, and ensure no test name, variable, assertion message, parser diagnostic, or documentation calls U+FFFE ill-formed or malformed. The UAX #15 Part1 test currently uses `ReferenceEquals` for its identity corollary. When removing the U+FFFE skip, make the conformance assertion compare string contents and leave the library's stronger same-instance optimization promise in its dedicated identity test.

The runtime differential tests also need an explicit policy for host globalization configuration. `.NET 8` doesn't unconditionally mean one ICU build: normalization can be backed by system ICU, app-local ICU, Windows NLS, or invariant globalization. The U+FFFE workaround must therefore be validated against the runtime configurations the project supports, while the bundled Unicode 15.0 conformance suite remains the standards oracle. Record the active backend/version in diagnostics or pin the CI environment so a platform change can't silently redefine what “matches .NET” means.
