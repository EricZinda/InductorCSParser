- Pass-through-text primitives: RuneNotIn, AnyChar, Not, Peek
    - Current state: Not implemented. The smallest core shipped `RuneIn` but not its complement `RuneNotIn`; it shipped no lookahead rules (`Peek`/`Not`); and it shipped no general "match one token of any content" rule (`AnyChar`). The pass-through-text idiom described in docs/ProgrammingModel.md and referenced by the Letters property comment in RuneSet.cs requires these primitives. Today there's no clean way to express "match everything up to this delimiter" or "match anything until this rule would fire," which is the most common real-grammar need after positive matching. Authors trying to write anything resembling a config file with comments, markup, or text with embedded tokens hit the gap immediately.
    - Four primitives, each small:
        - **RuneNotIn(RuneSet set)** — matches one token iff the token is exactly one rune AND that rune is NOT in the set. Mirror of RuneIn, predicate flipped. Key semantic detail: multi-rune tokens (emoji under GraphemeLexer) pass RuneNotIn because they aren't a single rune in any set. This is what makes the idiom work for user-typed text.
        - **AnyChar()** — matches any single token of any content, as long as the lexer isn't at EOF. Under RuneLexer that's any rune; under GraphemeLexer any grapheme, including multi-rune ones like 👨‍👩‍👧‍👦. The "match one character, whatever it is" primitive.
        - **Not(Rule inner)** — negative lookahead. Opens a lexer transaction, runs inner.TryParse, rolls back regardless of outcome, and returns a zero-width success iff the inner rule FAILED. Consumes no input either way.
        - **Peek(Rule inner)** — positive lookahead. Same shape as Not but succeeds iff inner succeeded. Consumes no input.
    - The two idioms these unlock:
        - **Delimiter-based stops:** `ZeroOrMore(RuneNotIn(delimiterSet))` matches everything that isn't one of a small set of stop characters. Good for comments (`// anything up to \n`), quoted strings (`"anything up to the next "`), simple passthrough fields.
        - **Rule-based stops:** `ZeroOrMore(And(Not(stopRule), AnyChar()))` matches everything up to wherever stopRule would fire. Handles arbitrarily complex stop conditions (multi-character terminators, context-dependent boundaries).
    - Priority: High. Without these, every non-trivial grammar author hits a wall immediately. The Letters property comment in RuneSet.cs already references these primitives as the answer to "how do I match anything else."
    - Cost estimate: 60-80 lines each, roughly 300 lines total with tests. Each rule is a standalone Rule subclass following the existing pattern (CharRule/RuneInRule are the templates). Not/Peek need access to the lexer's transaction API, which is already public.
    - Done when: all four rules exist, are reachable via Rules.RuneNotIn / Rules.AnyChar / Rules.Not / Rules.Peek, and there's a test for each that exercises both lexer modes (Grapheme and Rune). A final test writes an end-to-end pass-through grammar (e.g., a line-comment parser: `And(Literal("//"), ZeroOrMore(RuneNotIn(RuneSet.Single('\n'))))`) to confirm the idiom works end-to-end.
