- OrRule should skip the single-element array and wrapper Symbol on the default Flatten path
    - Current state: OrRule.cs:21 returns `new Symbol(Id, FlattenType, new[] { symbol })` on every successful match. Every Or hit allocates a one-element `Symbol[]` plus the wrapper Symbol. In the JSON grammar's `Or(literalChar, escapeSequence)` (InductorJsonParser.cs:57), this fires once per character of every JSON string. On Big JSON with thousands of string chars, that's thousands of single-element arrays per parse.
    - Why now: Or is on the per-character hot path for any grammar with character-class alternatives. The wrapper Symbol it produces is semantically pure overhead under the default `FlattenType.Flatten` (set at OrRule.cs:8); the post-hoc Flatten() pass would just splice the inner symbol back in, replacing the parent. We can do that splice at parse time and avoid the allocation entirely.
    - Design: When `OrRule.FlattenType == FlattenType.Flatten` (the default), return the inner `symbol` directly instead of wrapping it. When the user has explicitly overridden the FlattenType to None (so they want the Or wrapper to appear in the tree), keep the current behavior. The check is one branch at OrRule.cs:21.
    - Edge cases: An Or with a custom SymbolId set via `.As("...")` is the user asking for the wrapper to be visible. The As-naming sets a non-default Id but typically leaves FlattenType as Flatten. Need to decide whether `.As(...)` on an Or should preserve the wrapper. Probably yes: the named version is documentation in the tree. Implementation: only skip the wrapper when both FlattenType is Flatten AND Id is the default OrRule Id (whatever the convention is for unnamed rules; needs a quick check of how SymbolId defaults work in Rule's constructor).
    - Impact estimate: Per-character allocation reduction on JSON string bodies. Big/Long/Wide should all show measurable Mean improvement (not just Allocated) because the per-char hot loop is doing less GC pressure work.
    - Done when: OrRule's default-flatten path returns the inner symbol unwrapped; named Or rules (via `.As(...)`) still produce a wrapper; a test confirms tree shape matches expectation in both modes; benchmark shows further Mean and Allocated improvement on Big/Long.
    - Verification: Same harness. Pay attention to the Mean column on this one; p100 and p200 mostly affect Allocated, but p300 hits a per-character path so Mean should move too.
