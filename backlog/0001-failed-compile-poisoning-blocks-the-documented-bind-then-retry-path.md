# A Compile that fails on "LateBoundRule was never bound" poisons the touched rules, so following the error message's own advice (Bind, then Parse) throws "build a fresh grammar instance"

    - The unbound-LateBound error message tells the user exactly how to recover: "Rule 'x' is a LateBoundRule that was never bound. Call .Bind(targetRule) before calling Parse or Compile." (src/InductorParser/LateBoundRule.cs:172-173, and the FlattenType-walk copy at 196-197). But that throw happens inside Compile's poisoning try (src/InductorParser/Rule.cs:802-871): `ValidateAll` runs at line 812, the catch at 867-871 calls `MarkInvalidAfterFailedCompile` (lines 1908-1912), and every touched rule gets `_invalidCompileReason` set. `Bind()` itself still succeeds afterward (the rules aren't sealed), which makes the trap worse: the fix appears to take, then the next Parse's auto-compile hits `CheckNoSealedReachableRules` (lines 1925-1933) and throws "Rule 'Or' can't be compiled because a previous Compile attempt failed after mutating this rule graph. Build a fresh grammar instance before compiling again."
    - User-visible consequence: the recursive-grammar bootstrap pattern the LateBoundRule doc itself recommends (declare the LateBound, build the graph, Bind at the end) becomes unrecoverable if the user Parses once before remembering the Bind call. With the static-readonly-field grammar pattern, "build a fresh instance" means restarting the process. Found on 2026-07-02 while reviewing commit 05eb5b2 ("failed mutating Compile now invalidates touched rules", 2026-05-29). That commit deliberately kept the pre-mutation failures (duplicate names, duplicate explicit ids, those checks run before the try) retryable, and the poisoning is the right call for the normalization pass, which really does mutate stored literals in place (see docs/PotentialBugSources/failed-mutating-compile-attempts-must-poison-touched-rules.md). The gap is that `ValidateAll` is a pure validation pass, and the only mutations that precede it inside the try (the two id-assignment passes at lines 805-809) are retry-safe by construction: they skip rules whose `_idAssigned` is already set and re-probe `usedIds`, so a second Compile after Bind produces the same ids.
    - Verify the Bug (Write Test First): in src/InductorParser.Tests (NUnit), likely alongside the existing LateBoundRule tests:
      ```csharp
      var expression = new LateBoundRule("expression");
      var term = Or(Integer(), And(Token('('), expression, Token(')')));
      Assert.Throws<InvalidOperationException>(() => term.Parse("1")); // "never bound"
      expression.Bind(term);              // do exactly what the message says
      var result = term.Parse("1");       // pre-fix: throws "Build a fresh grammar instance"
      Assert.That(result.Success, Is.True);
      ```
      Run: `./test.sh recursive --filter "FullyQualifiedName~<test name>"`. Pre-fix the second Parse throws instead of succeeding.
    - Fix: shrink the poison region so validation-only failures stay retryable. Move `ValidateAll` (and if possible the id passes, which can't throw on a graph that passed the pre-try uniqueness checks) out of the try, so the try covers only the genuinely destructive region: the normalization pass, the re-run id pass, SealAll, and StampNormalizationForm. Alternatively keep the structure and have the catch skip poisoning when the failure came from `ValidateAll` (a marker exception type or a flag set once the normalization pass starts). The first shape is cleaner. Either way, also reword or verify the two remediation messages that currently direct users into the refused path after a *normalization* failure (Rule.cs:1831-1832 "pass a different normalization form to Compile (or null to disable normalization)", and the ReportNormalizeFailure advice at 1797): after a poisoning failure those suggestions must say the retry needs a fresh grammar instance.
    - Verify the Fix: the new test passes, and the existing poisoning regression tests from 05eb5b2 still pass (a failed *normalization* compile must still refuse retry). Full `./test.sh recursive` green.
