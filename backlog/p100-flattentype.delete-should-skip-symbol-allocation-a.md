- FlattenType.Delete should skip Symbol allocation at parse time, not post-hoc
    - Current state: OptionalWhitespace() is defined in Rules.cs:97 as `ZeroOrMore(RuneIn(RuneSet.Whitespace)).Flatten(FlattenType.Delete)`. The Delete semantics only fire when a consumer calls Flatten() on the result tree (Symbol.cs:108). During parsing, every OptionalWhitespace() call still allocates a `new List<Symbol>()` (BetweenInclusiveRule.cs:60), a wrapper Symbol (BetweenInclusiveRule.cs:83), and one leaf Symbol per whitespace rune matched (RuneInRule.cs:43). The JSON benchmark calls OptionalWhitespace eight times per object member or array element; on a typical Wide JSON value that's hundreds of throwaway allocations per parse.
    - Why now: src/Benchmarks/README.md ranks InductorParser at 5x-34x SystemTextJson and 40-50x allocation. The README explicitly calls out parse-tree construction as "the first place to look" and "match and discard" as the missing primitive.
    - Design: Add `public static readonly Symbol Discarded` sentinel to Symbol.cs. In Rule.TryParse (the public entry that calls TryParseRule), check whether the rule's effective FlattenType is Delete and substitute Discarded for the returned Symbol. In AndRule.cs:31 and BetweenInclusiveRule.cs:68, skip `matched.Add(symbol)` when `symbol == Symbol.Discarded`. The post-hoc FlattenInto Delete branch (Symbol.cs:108) becomes dead code at parse time but stays in place for any tree built outside the parse path.
    - Edge cases: Discarded must still report a non-null return so the caller treats it as a successful match. The lexer position must still advance for matched discardable rules; the position update is on the lexer, not the Symbol, so this is automatic. Trace output should still show the matched-and-discarded rule so debugging isn't impaired.
    - Impact estimate: Roughly half of the wrapper Symbols on JSON Wide/Long shapes go away (every OptionalWhitespace, plus any user grammar that uses .Flatten(Delete) on separators or noise). Bigger wins on grammars with whitespace-heavy input (the JSON benchmark inputs have zero whitespace, so the wins are limited to the wrapper allocation, not leaf chars).
    - Done when: Symbol.Discarded sentinel exists; the JSON benchmark's Allocated column drops measurably on Wide/Long; the existing test suite passes (some tree-shape tests will need updates to match the new "Delete is filtered before tree assembly" reality); a new test verifies that `OptionalWhitespace()` followed by `.Compile()` followed by `.Parse(" ")` produces a tree with no whitespace nodes; Symbol.FlattenInto's Delete branch still works for trees built by hand outside the parse path.
