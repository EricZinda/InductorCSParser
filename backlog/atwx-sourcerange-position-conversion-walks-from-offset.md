# SourceRange position conversion walks from offset 0 on every node, so extracting positions across a parse tree is quadratic

    - `Symbol.SourceRange` (src/InductorParser/SyntaxTree/Symbol.cs, the getter around line 307) builds two `SourcePosition.From` per node, one for the start offset and one for the end. `SourcePosition.From` (src/InductorParser/SyntaxTree/SourcePosition.cs:74) eagerly computes all four units, and two of them walk the input from offset 0: line/column via `SourcePositionConverter.ToLineColumn` (src/InductorParser/SyntaxTree/SourcePositionConverter.cs:20, a char-by-char scan from 0 to charIndex) and token index via `GraphemeClusterIndex.CountClustersUpTo` (src/InductorParser/Lexing/GraphemeClusterIndex.cs:178, a bool-array scan from 1 to charIndex). Both are O(charIndex) per call.
    - User-visible consequence: a consumer that reads positions across a whole parse tree (an LSP server emitting diagnostics or semantic tokens, a typed-AST projection that records each production's span, a pretty-printer) reads a `SourceRange` per node. A node at offset P costs O(P), and the offsets of N nodes spread across an L-char input sum to O(N x L), so position extraction is quadratic in document size. Measured on a word-per-line grammar reading `SourceRange` on every node under `PreserveAllSymbols`: 144K chars took ~36,900 ms and the size-doubling ratio was 3.85x (quadratic). Even pure-ASCII grammars pay this cost: the `ReferenceEquals(originalInput, parseInput)` fast path in `SourceRange` only skips the normalized-position translation (`NormalizedPositionMap`), not these two walks. The error path is unaffected (one conversion per parse), which is why no existing test or benchmark surfaces it.

    - Fix: build a per-input index once and answer each query sub-linearly, using the same `ConditionalWeakTable`-keyed cache idiom `GraphemeClusterIndex` already uses.
      1. New `LineStartIndex` in src/InductorParser/Lexing/: cache a sorted array of line-start char offsets (offset 0 plus one past each break), then resolve line/column with a binary search for the last line start <= charIndex (line = its index, column = charIndex - that start). The break set is UAX #18 Annex C (LF, CRLF as one break, lone CR, VT, FF, NEL, LS, PS). Mirror the old `ToLineColumn` loop exactly so the result is unchanged, and keep it in step with `TokenSet.IsLineTerminator`. Point `SourcePositionConverter.ToLineColumn` at it.
      2. Back `GraphemeClusterIndex.CountClustersUpTo` with a build-once cumulative-count: under the existing `_walkLock`, after a full `EnsureWalkedTo(_input.Length)`, either take an O(1) identity shortcut (return charIndex) when the input has no multi-char cluster (every position is its own cluster start, the common ASCII/BMP case, zero extra memory) or build a prefix-sum `int[]` (count of cluster starts in [1, i]) and return `cumulative[charIndex]`. Publish via a `volatile` flag written last, same acquire/release argument as `_walkedTo`.
