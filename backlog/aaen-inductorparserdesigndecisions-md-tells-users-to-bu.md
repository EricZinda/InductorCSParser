# InductorParserDesignDecisions.md tells users to build emoji/flag sets with TokenSet.Runes, which throws on multi-rune clusters

    - What's wrong: the "Matching Multi-Rune Tokens" section of [docs/InductorParserDesignDecisions.md](../docs/InductorParserDesignDecisions.md) (line 364) gives two expressions in its OneOf bullet: `OneOf(TokenSet.Runes("👋🏽🇺🇸"))` "matches the listed multi-rune tokens via the set's multi-rune array", and `TokenSet.Letters | TokenSet.Runes(USFlagGrapheme)` for "letters or these flags". `TokenSet.Runes(string)` (src/InductorParser/TokenSet.cs, the factory around line 1031) walks its input grapheme by grapheme and throws ArgumentException on any multi-rune cluster, on purpose (its own remarks say to use `Graphemes` for clusters). 👋🏽 is a two-rune cluster (U+1F44B + U+1F3FD) and 🇺🇸 is a two-rune cluster (U+1F1FA + U+1F1F8), so both doc expressions throw at grammar-build time. A user pasting either one gets an exception on the exact feature the bullet is teaching.
    - Verified on 2026-07-02 (net8.0, scratch NUnit battery, deleted after the hunt): `TokenSet.Runes("👋🏽🇺🇸")` throws `Runes(string) input "👋🏽🇺🇸" contains a multi-rune grapheme cluster ("👋🏽") at UTF-16 offset 0 ...`, and `TokenSet.Letters | TokenSet.Runes("🇺🇸")` throws the same way. The corrected form works: `TokenSet.Graphemes("👋🏽", "🇺🇸")` contains both clusters and `OneOf` over it parses "👋🏽" successfully.
    - The same broken idiom appears in two more prose spots in the same doc (spotted after the 2026-07-02 master merge): line 167 ("character classes like `TokenSet.Letters | TokenSet.Runes(USFlagGrapheme)` mean what they read") and line 205 ("what makes `OneOf(TokenSet.Letters | TokenSet.Runes(USFlagGrapheme))` accept letters and the US flag"). Both present the throwing expression as working code, so the fix should sweep the whole file for `Runes(USFlagGrapheme)` and `Runes("👋🏽🇺🇸")`, not just the line-364 bullet.
    - This is a known pattern with a prior fix that missed this file. The 2026-06-03 hunt fixed the same broken idiom in primer1.md and InductorParserReference.md (docs/BugSearchLog/0-2026-06-03-primer1-reference-tokenset-runes-flag-example-throws.md) and wrote the pattern doc docs/PotentialBugSources/2026-06-03-doc-example-uses-runes-for-a-multi-rune-cluster-member.md. TokenSet.cs's own class doc gets it right (`TokenSet.Letters | TokenSet.Graphemes(USFlagGrapheme)`, TokenSet.cs line 32). The DesignDecisions.md instance survived that sweep.
