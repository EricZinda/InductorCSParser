# SourceRange constructor is internal — can't synthesize compound spans

    - Where this came up: the Newsboat sample's `RewriteAnd` and `RewriteOr` AST records originally carried a `SourceRange?` field meant to span "from the start of the left subtree to the end of the right subtree." Building it would have been `new SourceRange(leftRange.Start, rightRange.End)`, which compiles inside the `InductorParser` assembly but not from sample / consumer code, because `SourceRange`'s constructor is `internal`. The sample dropped the field as a workaround. (Fields kept on the `RewriteComparison` record because those come straight from `result.SourceRangeOf(comparisonNode)`.)
    - Why this is friction: a compound AST node almost always wants a span that spans its children. A consumer of the library is going to want to take "the source range of this comparison and the source range of that comparison" and produce "the source range of the And-expression that joins them." The library has all the pieces (SourcePosition is public; SourceRange has public Start / End getters), it just doesn't let the consumer assemble them.
    - Options, in order of preference:
        - Make the SourceRange constructor public. It's a value-type pair of public-getter SourcePositions. There's no invariant the constructor enforces that a consumer can't already produce by hand from the public Start / End. Letting them call `new SourceRange(start, end)` directly is the trivial fix. Probably the right fix.
        - Add a `SourceRange.Span(SourceRange a, SourceRange b)` factory that returns `new SourceRange(a.Start, b.End)`. Same thing with a slightly more readable call site, but you can't span more than two without a `.Reduce(...)` shape.
        - Document the workaround: track the underlying Symbol references on AST records and call `result.SourceRangeOf(symbol)` per node, accepting that compound nodes don't have a single Symbol to point at. Cheap, doesn't fix the actual gap, pushes work onto every consumer.
    - Done when: a consumer can write `new SourceRange(left.Start, right.End)` from outside the assembly, and the docs on SourceRange say so.
