- State machine doesn't surface WithError messages on failure
    - Current state: under `INDUCTOR_DEFAULT_ENGINE=statemachine dotnet test` nine fixtures fail because `result.ErrorMessage` from the SM is the generic `Parse failed at offset N: unexpected 'x'.` / `Unexpected end of input.` that `Rule.BuildErrorMessage` produces when the lexer's `DeepestFailureMessage` is null. The recursive engine sets `DeepestFailureMessage` from the rule's `WithError(...)` text the first time that rule records a failure at the deepest position, and the test suite locks that in across a wide range of rule shapes. The SM's `RecordFailure` path doesn't carry the rule's `WithError` text the same way, so the message never makes it back to `ParseResult.ErrorMessage`. Sample: `Not_fails_when_inner_matches` (`src/InductorParser.Tests/Rules/NotRuleTests.cs:38`) expects `"did not want an 'a'"`, gets `"Parse failed at offset 0: unexpected 'a'."`.
    - The full list: `Not_fails_when_inner_matches`, `Peek_fails_when_inner_fails`, `BetweenInclusive_WithError_message_surfaces_on_failure`, `Exactly_WithError_message_surfaces_on_failure`, `OneOrMore_outer_message_wins_when_inner_has_none`, `Deepest_failure_wins_across_multiple_WithError_rules`, `WithError_message_appears_when_that_rule_is_deepest_failure`, `RuneRun_requires_at_least_one_rune` (expected `"need a letter"`), `Fails_at_end_of_input` (expected `"wanted a grapheme"` from a `WithinGrapheme` bridge case).
    - Recommended path: trace the recursive engine's WithError attribution (`Lexer.RecordFailure` + the `DeepestFailureMessage` field) and replicate it in the SM's failure-recording path. The SM's `RecordFailure` opcode needs to carry the source rule's `ErrorMessage` (whatever `WithError("...")` set on the rule) so that when that failure becomes the lexer's deepest, the message rides along. For inlined rules with no Call frame, the lowerer should embed the rule's error message into the failure-recording opcode itself rather than looking it up via the call stack. For Not / Peek / WithinGrapheme (all of which the SM either lowers natively or bridges) the wrapper rule's error message has to win over the inner's "unexpected 'a'" generic, same as the recursive path. Worth checking whether `Stepper`'s Call/Return path already carries enough rule-id context to attribute failures correctly for cyclic rules; if so the gap is just on the inlined path.
