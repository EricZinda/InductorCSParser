- Lazy-allocate the children list in BetweenInclusiveRule and AndRule
    - Current state: BetweenInclusiveRule.cs:60 and AndRule.cs:14 both call `var matched = new List<Symbol>()` unconditionally on entry. For BetweenInclusive that matches zero times (a common Optional/ZeroOrMore case in any grammar with optional pieces), the list never receives an Add. Combined with the wrapper Symbol allocation that follows, every zero-match Optional or ZeroOrMore costs two heap objects for nothing.
    - Why now: Stacks with the Tier 1 Delete-skip work (p100). Once Discarded children are filtered out, many BetweenInclusive instances will be matching but adding nothing; the list allocation is then pure overhead in a hot path.
    - Design: Replace `var matched = new List<Symbol>()` with `List<Symbol>? matched = null;`. Lazy-init on the first non-null, non-Discarded child. When matched is still null at the end, return `Symbol.Empty` (a singleton with empty children list) instead of `new Symbol(Id, FlattenType, emptyList)`. Symbol.Empty needs to share the existing `EmptyChildren = Array.Empty<Symbol>()` field at Symbol.cs:14.
    - Edge cases: AndRule almost always fills its list (every child has to match for And to succeed), so the lazy-init path mostly only fires when the rule has zero children, but Rules.cs:48 already rejects empty And, so this is dead in practice for And. The win is real for BetweenInclusive only. Keep the change in both for symmetry and simplicity.
    - Impact estimate: Smaller than p100 in raw allocation count, but every saved BetweenInclusive list is also one less GC-survived object. Compound effect with p100 is what matters.
    - Done when: BetweenInclusiveRule and AndRule both use lazy `List<Symbol>?` allocation; a test confirms `Optional(Char('x')).Parse("")` returns a Symbol with no children and zero non-leaf allocations beyond the result Symbol itself; benchmark Allocated column shows further reduction beyond p100.
    - Verification: Same harness as p100. Diff against the post-p100 baseline so this tier's contribution is visible separately.
