# Or-Preserve wrapper vs. inner-rule dispatch needs a worked example in the docs

- Surfaced by: the TOML 1.0 port (E2ESamples/Toml). The grammar defines `Table = Or(ArrayTable, StdTable).As("table").Preserve()` so the AST consumer can dispatch on "this top-level Symbol is a table header, of either kind." That's the natural shape: one named wrapper, two concrete kinds underneath.
- The trap: `symbol.Is(StdTable)` returns false on the wrapper Symbol. `Is` matches against the symbol's own grammar-rule id, not against any descendant's id. So the consumer's `if (symbol.Is(KeyVal)) ... else if (symbol.Is(StdTable)) ... else if (symbol.Is(ArrayTable)) ...` dispatch silently ignored every table header — they all matched against `Table`, not against `StdTable` / `ArrayTable`. The TomlParser then fell through to "currentTable stays at root" and dumped every table's keyvals into the root, producing a `Duplicate key 'ip'` error several keyvals later when two `[server.alpha]` and `[server.beta]` tables both tried to add `ip` to the same root scope. The bug looked like a table-merging bug; the actual cause was a missed dispatch.
- The fix at the use site: drill into the wrapper. `if (symbol.Is(Table)) { var inner = symbol.Children[0]; if (inner.Is(StdTable)) ... }`. Two-line change once you know the shape. But spending 20 minutes hunting down `Duplicate key 'ip'` first is the friction.
- The JsonGrammar example in src/InductorParser.Tests/E2EExamples/JsonGrammar.cs doesn't illustrate this case. Its `value = Or(JsonString, JsonNumber, JsonObject, ...)` is bound via `LateBoundRule` and consumed by walking children rather than by a top-level `value.Preserve()` wrapper. A new user reading JsonGrammar wouldn't learn the wrapper rule; they'd hit it when they tried to add `.As(name).Preserve()` to an Or for "I want this dispatchable as a category" and then their `Is(InnerRule)` checks would silently skip.
- Two reasonable fixes (do both):
    - Document the wrapper-vs-inner pattern in the `Rule.As` and `Rule.Flatten` doc comments. One worked snippet: "When you wrap an `Or` in `.As(name).Preserve()`, the resulting Symbol is the wrapper, not the matched alternative. Dispatch via `symbol.Children[0].Is(InnerRule)`."
    - Add a worked example to docs/ that explicitly shows a "category wrapper over alternatives" grammar (similar to TomlGrammar.Table = Or(StdTable, ArrayTable).Preserve()) and the consumer code that drills into Children[0].
- Open question: should `Symbol.Is(rule)` optionally pierce one level of wrapper? An overload `symbol.IsOrWraps(rule)` that returns true when the symbol is `rule` OR has exactly one child that is `rule` would let consumers write `if (symbol.IsOrWraps(StdTable))` and skip the dispatch step. Smaller surface change than reworking `Is` itself, opt-in by name.
- Done when: the docs teach the pattern by example. A new user porting a grammar with category wrappers doesn't have to discover this empirically by chasing a "duplicate key" error to find an unmatched dispatch case.
