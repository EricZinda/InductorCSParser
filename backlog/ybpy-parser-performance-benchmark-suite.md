- Parser performance benchmark suite
    - Current state: no perf tests anywhere. src/InductorParser.Tests/ is NUnit functional tests only. We don't know where InductorParser stands against other C# parsers, we have no way to detect future perf regressions, and we can't make credible performance claims.
    - Recommended path: fork Parlot's BenchmarkDotNet suite at https://github.com/sebastienros/parlot/tree/main/test/Parlot.Benchmarks (MIT-licensed). Its JsonBench.cs already compares Parlot compiled, Parlot non-compiled, Pidgin, Sprache, Superpower, Newtonsoft.Json, and System.Text.Json across four generated JSON shapes: Big (4x4x3 balanced), Long (256x1x1 wide-at-root), Deep (1x256x1 nested), Wide (1x1x256 many properties). Inputs are generated in GlobalSetup(), no files to check in.
    - Additions beyond the fork: adapters for InductorParser and Pegasus (https://github.com/otac0n/Pegasus, the only other PEG parser generator in the C# ecosystem). Pegasus is important because without it the benchmark answers "how do we compare to parser combinators" but not "is our PEG competitive." Final table has nine parsers: two hand-written baselines, five combinator rows, two PEG generators.
    - Files to create: src/InductorParser.Benchmarks/ as a new net8.0 project; Json/JsonBench.cs forked from Parlot; Json/InductorJsonParser.cs with a JSON grammar in InductorParser's fluent API; Json/PegasusParsers/Json.peg + wrapper (hand-written, no upstream sample); PidginParsers/, SpracheParsers/, SuperpowerParsers/ copied verbatim from Parlot; Program.cs runner; README.md with absolute numbers from one machine as a regression baseline.
    - Cost estimate: one day. Most of the effort is writing two JSON grammars (InductorParser and Pegasus). The harness and competitor adapters are lifted as-is. Pegasus integrates via MSBuild (Build Action = PegGrammar) so .peg files compile to .peg.g.cs at build time.
    - Done when: dotnet run -c Release --project src/InductorParser.Benchmarks -- --filter *Json* produces a BenchmarkDotNet table with all nine parsers across the four JSON shapes; InductorParser and Pegasus produce semantically equivalent trees on the same input (spot-check, not a bench); README captures absolute numbers so regressions are visible.
    - Out of scope for the first pass, revisit if the numbers are interesting: nativejson-benchmark corpus (canada.json, citm_catalog.json, twitter.json) for cross-language reconciliation; FParsec lifted from Pidgin.Bench; ANTLR C# target via grammars-v4; expression/SQL/identifier/regex benchmarks from Parlot's harness.
